# 水槽探検：ゲーム構想と開発ロードマップ

最終更新：2026-11-28（ゲームの基本方針の確定：1 章の「ゲームの基本方針」・食事と栄養：11 章）。以前：同日（ゴカイ：10 章）、2026-11-27（アプリ化：9 章）

このページは、水槽探検（`aquarium.html`）をどこへ育てるかの共通の地図です。
「確定」は今後の作業の前提にしてよい方針、「検討中」は遊んで確かめてから決める案です。
実装の詳細は各機能の報告（`docs/aquarium/<機能>/report.md`）とコードを正とします。

## 1. 基本コンセプト

プレイヤーは小さなカニ。水槽の中で暮らし、冒険する。

- 砂を掘って巣穴を作り、壁や天井を歩き、隠れた生き物を見つけて仲間を増やす。
- 仲間はふだん水槽で自由に暮らし、呼ぶといっしょに冒険する。
- 水槽では植物を育て、生き物を殖やし、環境を整える。珍しい模様・性質の個体が生まれる楽しみがある。
- 始まりの水槽は、冒険から帰ってくる拠点。隣の水槽は最初から見えているが、能力や仲間の協力を得て初めて行ける。
- 冒険先で見つけた生き物・植物を拠点へ持ち帰り、暮らしや栽培に使う。
- **生存管理のペナルティで急かさない。環境を整えるほど新しいことが起きる**ゲームにする。

### ゲームの基本方針（2026-11-28 確定。今後の設計の前提）

| 柱 | 方針 |
| --- | --- |
| 目的 | **好奇心に従って未知の場所へ進む探索**。到達した場所から次の目的地が見える、段階的な探索構造にする（見えているのに、いまの体・仲間では届かない所が次の目標になる） |
| 手段 | **地形や生き物への物理的な干渉と試行錯誤**（掘る・盛る・挟む・引く・運ぶ・食べる・登る）。障害を突破する方法は一つに限定しない（例：高い段差は 砂を盛る / 壁を登る / 泳げる体になる / 仲間の力を借りる） |
| 報酬 | 成長（脱皮）・能力の獲得（世代交代で新しい身体的特徴）・生き物の発見・仲間の増加 |
| 成長の循環 | **食事で栄養を蓄積**（経験値に相当。時間では減らない）→ **脱皮で個体の能力が成長** → **世代交代で遊泳脚などの新しい身体的特徴を獲得**。身体的特徴によって得意・不得意が生まれる（泳ぐのが得意な体は掘るのが苦手、など） |
| 世代と操作 | 親や子孫は水槽内に残り、**操作するキャラクターを切り替えられる**（行きたい場所・したいことに合わせて個体を選ぶ） |
| 初期の体 | **初期のカニは泳げない**。遊泳能力は身体構造の進化（世代交代で遊泳脚を得る）で獲得する（いまの遊泳＝ジャンプの長押しは、初期の体からは外す方向。12 章） |
| しないこと | 空腹による能力低下や餓死は設けない（食べないと困る、ではなく、食べると育つ） |

### 確定した方針

| 方針 | 内容 |
| --- | --- |
| 急かさない | 空腹・水質悪化などで死ぬ・失うペナルティは入れない（空腹による能力低下・餓死も無し）。食べ物・環境は「良くするほど得をする」プラスの効果だけ |
| 栄養（2026-11-28） | 食べた量に応じて増える蓄積型の成長資源（経験値に相当）。時間では減らない。脱皮（能力の成長）の元になる（11 章） |
| 拠点と冒険 | 始まりの水槽が拠点。隣の水槽は見えるが、能力・仲間の協力で開放する |
| 仲間 | 見つけた生き物が仲間になる。自由生活と同行を切り替えられる。地形・ガラスを突き抜けない |
| 地形は残る | 掘った穴・盛った砂・手持ちの砂・見つけた場所・仲間はブラウザを閉じても残る（M1・M2 で実装） |
| 地形は作り変えられる | 掘る・盛るを何度でも重ねられ、後の編集が勝つ（掘った穴へ盛る・盛った砂を掘る）。砂は実際に掘った量だけ手に入る（M2） |
| 描画 | 方式 F v2（三角形 + 円盤）のドット絵の見た目を守る。比較ページ A〜F は変えない |
| 端末 | PC（キーボード・マウス）とスマホ（タッチ）の両方で同じ遊びができる |
| アプリ化（2026-11-27 確定） | **Tauri 2** を正式なアプリ化の基盤にする。ブラウザ版と Windows・Android・iOS 版で**同じゲームのコード**を保ち、違いは `AquaPlatform.ts` と `src-tauri/` だけに置く（9 章） |

### 検討中の案

| 案 | 迷っている点 |
| --- | --- |
| 仲間の種類と役割 | 種ごとに能力（運搬・掘削・照明など）を分けるか、個体の特徴（traits）で差を付けるか |
| 繁殖と遺伝 | 模様・色・大きさの遺伝の規則、レアの出方。図鑑を作るか |
| 自動化の範囲 | 収穫・運搬・加工のどこまでを仲間に任せるか。指示の出し方（場所の指定・役割の割り当て） |
| 隣の水槽への行き方 | 配管を通る・ガラスを越える・仲間に運んでもらう、のどれを最初の開放にするか |
| 巨大生物 | 敵にするか、避ける・やり過ごす相手にするか（急かさない方針と両立させる） |
| 操作キャラの切り替え | （方針は確定：親や子孫のカニを切り替える）。仲間の別の種（スナモグリ等）にも乗り移れるか。切り替えた後の元の個体の暮らし方 |
| 脱皮と世代交代の具体 | 脱皮で何が伸びるか（大きさ・握る力・掘る速さ・歩く速さ）、脱皮の間の無防備さを入れるか（急かさない方針と両立）。世代交代の起こし方（繁殖 9 番と同じ仕組みか）・特徴の遺伝の規則 |
| 工業と対戦 | 対戦モードは本編と別のモードにする前提。工業（加工の連鎖）をどこまで深くするか |

## 5. M1 の設計メモ

### セーブ
- IndexedDB に `current` / `backup` / `corrupt-*` の鍵で保存。検証を通ったデータだけ使う。詳細は [save-format.md](save-format.md)。
- 掘った穴は空洞（カプセル）の並びとして保存し、起動時に `DigField.restore` → `AquariumDigFx.flushAllAsync` で
  区画をすべて作り直してから当たり判定へ入れる（見た目と当たり判定が同じ瞬間に切り替わる）。
  保存前と再読み込み後で、空洞・区画ごとの三角形・当たり判定の値・隠した植物/小石が完全に一致することを確認済み。

### 最初の仲間：スナモグリ
- 砂の広場の端の砂に巣穴。近づくと触角と鋏の先が穴から出て動く。

## 6. M2 の設計メモ

詳しい結果は [ceiling-sand/report.md](ceiling-sand/report.md)。

### 天井歩き
- 張り付いている間、スティックの前・右に当たる「面に沿う向き」を面に貼り付けて持ち、面の向きが変わるたびに同じ回転で回す。
  押したまま床 → 壁 → 天井 → 反対側の壁へ進んでも、進む向きが途中で反転しない。離したら、いまのカメラと面から決め直す
  （壁 = 従来の「壁へ = 上」、天井 = 画面の前・右）。
- 体の向きは「上 = 面の法線・前 = 体の前」の座標軸で持つ（逆さの近くで「上 → 法線」の最小の回転を使うと、体が急に回るため）。
- カメラは傾けない（画面の上下は反転しない）。天井では注視点を面から空いている所まで離し、カニを下から見上げる。

### 砂の回収と再配置
- 地形 = 元の砂（高さ場）に、掘った空洞と盛った砂を **編集した順に** 当てる（同じ種類が続く間は 1 つの層にまとめる）。
  保存も同じ順の 1 つの並び（版 2）。掘るだけなら従来とまったく同じ値（版 1 のデータは同じ形に戻る）。
- 手に入る砂 = 実際に取り除いた体積（前後の形を格子で比べる）。空振り・掘った穴の中を太らせただけ・同じ所の掘り直しでは増えない。
  盛るときは足した体積だけ減る。体積の測定はフレームに分けて行う（1 フレーム 1.5 ms まで）。第 10 段階で持てる量の上限（容量 4 = 80 杯。
  超えた分は捨てていた）をなくし、手持ちが地形（掘った − 盛った）より少なければ戻す見直し（救済）を足した（[hybrid-gait/report.md](hybrid-gait/report.md)）。
- 盛った砂も区画ごとの作り直し（見た目と当たり判定を同じ瞬間に切り替える）を通る。ガラス・管・発見物・底のまわりの打ち切り、
  カニ・仲間との距離で、保護する物を貫かない・生き物を埋めない。

## 7. 今後の重要な操作改善案

### 生き物を直接つかんで引っ張って抜く（✅ 1 種で試作済み：引っこ抜き 2.0）

ハサミで挟んで引っ張る形で実装した（[burrow-pull/report.md](burrow-pull/report.md)）。ゴカイの細長い体の節ごとの質点と、
種ごとの抵抗の差（WormSpec・手応えの設定）は 2026-11-28 に実装した（[gokai/report.md](gokai/report.md)）。指・マウスで直接つかむ案、
個体の特徴（traits）による抵抗の差は未着手。以下は当初の構想（長押しのゲージ約 0.6 秒からの発展）。

- **操作**：穴から出ている体の一部（触角・鋏・尾）を指 / マウスでつかみ、引きたい向きへドラッグする。離すと手放す。
  PC はマウスの左ドラッグ、スマホは画面の指（カメラのドラッグと区別するため、つかめる部分の上から始めたときだけ）。
- **手応え**：生き物は引く力に抵抗し、引くほど体が伸び、緩めると縮んで戻る（ばねと減衰）。引く強さ・向き・タイミングで抜けやすさが変わり、
  抵抗が弱まった瞬間に一気に引くと、最後に勢いよく抜ける。釣りゲームのような「張り・緩め」の駆け引きを重視する。
- **伝え方**：体の伸び・砂の盛り上がり・震え・音・（スマホは）振動で、いま強く引きすぎている / 抜けそう、が分かる。
  ゲージの数値は出さないか、補助として小さく出す。強く引きすぎても失敗にはしない（急かさない方針：手放すだけ）。
- **応用**：細長い虫（ゴカイ等）は体の節ごとに伸び縮みし、途中で切れないよう加減して引く。種ごとに抵抗の強さ・周期・伸びる長さを変え、
  個体の特徴（traits）にもつなげられる。
- **実装の見通し**：生き物の体を数個の節（質点とばね）で表し、つかんだ節に指の位置へ向かう力を加える。抜ける判定は
  「穴から出た長さ」と「抵抗が弱い時間に引いた量」。見た目は既存のメッシュの骨を節に合わせて曲げる。いまの長押しは、
  慣れない人向けの補助（押し続けると自動で引く）として残す案。
- **確かめること**：スマホでカメラのドラッグ・スティックと指がぶつからないか、片手で遊べるか、抜けるまでの時間（数秒）、
  「抜けた」瞬間の気持ちよさ。M3 で生き物の種類を増やすときに、まず 1 種で試作する。
- **土台（済み）**：ハサミで物を挟む MVP（`AquaGrab.ts`）で、つかみ点 ↔ ハサミのばね・握る力の上限・反作用・滑り落ち・ハサミの IK が
  できた。生き物の節（質点）を「挟める物」として扱えば、この仕組みのまま引っ張れる。

## 12. 成長の循環の設計メモ（次の段階へ）

- **脱皮（6a）**：栄養の合計が `GROWTH.moltAt` の段階に届いたら脱皮できる（自動か、安全な所で操作して行うか）。殻を脱ぐ演出・脱いだ殻が残る・
  一回り大きく（`crabModel` の大きさ・`CrabController.RADIUS`）・握る力（`GRIP_FORCE`）・掘る速さが伸びる。栄養は減らさずに「次の段階」を見る
  （経験値の方式）か、脱皮に使って減らすかは試して決める（いまの保存は合計と種類ごとの量なので、どちらにも移れる）。
- **世代交代（6b）**：子は親の特徴を受け継ぎ、まれに新しい身体的特徴（遊泳脚・大きな鋏・長い脚など）を持つ。特徴ごとに得意・不得意
  （遊泳脚＝泳げるが歩きが遅い、大きな鋏＝重い物を運べるが細かい物をつかみにくい 等）。保存は個体ごとの traits。
- **遊泳**：初期のカニは泳げない方針。いまのジャンプ長押しの遊泳は、遊泳脚を持つ個体だけの能力へ移す（移すまでは今の動きのまま）。
  水面・高い所・隣の水槽の上など「泳げる体になって初めて届く所」を探索の段階に組み込む。
- **操作キャラの切り替え（6c）**：親・子孫は水槽に残り、切り替えられる。切り替えた後の元の個体は仲間と同じ自由生活（`AquaBuddy` の仕組みを流用）。
- **段階的な探索**：到達した場所から次の目的地が見える配置（見晴らし・ガラス越しの隣の水槽・水面の穴）を、能力の段階（脱皮・遊泳脚・仲間）と対応させる。
  突破の方法は 1 つに限らない（砂を盛る・登る・泳ぐ・仲間）。
