## 1. ワールド生成時間の増加（最優先）

### 結論

- 同じ時間帯・同じ条件で交互に測った比較では、**約 2.7 秒 → 約 3.6 秒（+0.9 秒、約 +33%）**。
- 先の作業報告では「約 4.6 秒 → 6〜7 秒」と書いたが、これはマシンの負荷が違う時間帯の値を比べたもので、
  変更していない処理（底床の網など）まで 1.4 倍前後に遅くなっていた。増加の割合は上の +33% の方が正しい。
  絶対値はマシンの混み具合で 1.5 倍ほど揺れるので、**比較は必ず同じ時間帯に交互に測る**こと。
- 増加分の半分弱は苔（C 側の円盤）を岩・流木の表面に付ける処理、残りは新しい岩・流木の三角形化、
  日照の格子（`solid()` の対象が増えた分）、新しい小さなメッシュ（貝殻・光る石・魚・エビ）。

### 計測の条件

- 2026-11-22、開発サーバー（Vite dev、ポート 5181）、Windows 11 のデスクトップ Chromium（Claude アプリ内ブラウザ）、
  画面 800×600 の iframe で `aquarium.html` を開き直して `window.__aqua` の値を読む。
- 順番：現在 3 回 → `src/` を一時退避して `47e549e` 3 回 → 現在 2 回（負荷の変化を挟んで確認）。値は回の中央値（ms）。
- 内訳の名前は `main.ts` の `__aqua.buildPhases`（三角形側）と `__aqua.plantTimes`（円盤側。今回追加）。

### すでに入れた対策

- 外接箱が丸ごと水中（または水上）で、苔の条件に合う点が 1 つも無い物は表面探索をしない（`mossOnSurface`）。
- 流木の SDF：枝ごとの外接球までの距離が `d + k` 以上なら、その枝の計算を省く（`smin` の性質上、結果は変わらない）。
- 苔玉は「全面を覆う」処理だけにし、ふつうの陸地の苔の処理から外した。

### 次に検討する案（効果の大きそうな順）

1. **岩の穴（くり抜き）の計算を省く**：`smax(d, -hole, k)` は `hole ≥ k - d` なら `d` のままなので、
   穴の外接球から遠い点では穴の計算を省ける（流木と同じ考え方、結果は変わらない）。洞窟・崖に効くはず。
2. **苔の表面探索の刻みを物ごとに変える**：洞窟の内側・小屋の中など、ふだん見えにくい面は刻みを粗くする。
3. **`solid()` の対象の絞り込み**：岩・流木を粗い格子に登録し、近くの物だけ調べる（日照の格子・底床・苔の全部に効く）。
4. **生成を Web Worker に移す / 段階的に描く**：読み込み中も画面が固まらないようにする（時間そのものは減らない）。
5. **生成結果をビルド時に焼いて配る**：起動時の計算をほぼ無くせるが、配る量（メッシュ約 47 万三角形 + 円盤約 17 万）が増える。

### 測り直し方

開発サーバーで任意のページを開き、ブラウザのコンソールで：


## 2. 流木の小屋の中でカメラが近づきすぎる

- 小屋（`AquariumWorld.buildWoods` の `hut`）の内側は半径 約 1.3。冒険カメラは遮蔽を避けて最短 0.5 まで寄るので、
  中に入るとカニが画面の大半を占め、枝が手前を覆って暗く見える。
- 入口（奥側＝岩の柱の側）の外から覗く視点では中がきれいに見える。
- 案：狭い場所（遮蔽で `dist` が小さい間）は注視点を少し上げて見下ろす角度にする / 小屋の範囲ではカメラを入口の外に固定する /
  小屋の屋根の一部を開ける。

## 3. shore 岩が地形に埋まっている（前のコミットからの問題）

- `AquariumWorld.buildRocks` の `shore`（コメントは「浅瀬：汀線の近くの岩」）は中心 (2.8, 2.9, 6.4)・縦の半径 1.0 で、
  てっぺんは y = 3.9。その場所の底床の高さは約 4.98 なので、**岩全体が底床の下に埋まっていて見えない**。
- 判定・見た目・苔の処理の対象には残っているので、生成時間だけ使っている（表面探索 約 25 ms）。
- 案：底床の高さに合わせて中心の y を約 5.0 に上げる（汀線から顔を出す岩になる）か、外す。上げる場合は浅瀬の高台
  （中心 2.4, 3.6）とエビの住みか（0.6, 5.6）との位置関係を確認する。

## 4. 比較ページ（index.html）の方式 A〜F の画素一致を今回は確認していない

- 共有の `src/render/shaders.ts` に足したもの（水中の水の流れ・陸地の色味と木漏れ日・水中の風の弱め）は、
  すべて `#ifdef PPP_WATER` の中にあり、比較ページのマテリアルは `PPP_WATER` を定義しないので、仕組みの上では変わらない。
- 確認したのは「比較ページが表示され、コンソールにエラーが無い」ことだけ。変更前後の画素比較はしていない。
- 案：`docs/compare/tools/`（撮影の手順）で既定の視点を変更前後で撮り、画素の差が 0 であることを確かめる。

## 5. スマホ実機での動作・性能を確認していない

- 確認したのはデスクトップのブラウザの画面サイズの切り替え（縦 375×812 の端末の真似、横 812×375）での配置だけ
  （場所の名前の表示・見晴らしの表示が左上の表示と重ならないこと、タッチ用のボタンが出ること）。
- 実機での描画の速さ（三角形 約 47 万 + 円盤 約 17 万）、生成時間（デスクトップで 2.7 → 3.6 秒。スマホの CPU では数倍かかる見込み）、
  タッチ操作（ジャンプ長押しの遊泳で柱のてっぺんへ届くか、2 本指ズーム）、発熱は未確認。
- 案：実機で `__aqua.buildMs`・HUD の FPS を記録する。重ければ `pixelScale`・円盤の密度（`AquariumRenderer.surfelDensity`）・
  水草の森の本数を下げる設定を用意する。

# 追記：縦穴式オーバーフロー・濾過槽・水槽の外（`feat/aquarium-sump`）

水槽の真下に濾過槽を置き、水面の縦穴 → 透明な排水管 → 濾過槽 → 水槽台の外（部屋）→ 給水管で水槽へ戻る、の一周を追加した。
定義は `AquariumStand.ts`（当たり判定・水位・水流・区画）、見た目は `AquariumStandBuild.ts`（不透明）と
`AquariumPlumbingFx.ts`（透明な管・アクリル・水面・管の中の水）。

## 6. 生成時間がさらに約 0.6 秒（約 10%）増えた

- 同じ時間帯に基準（`43ec95b`）と交互に測った値（2026-11-22、Vite dev、アプリ内ブラウザ）：
  基準 5695 / 5632 ms、今回 6490 / 6060 ms。この時間帯はマシンが混んでいて、基準の値も前回の記録（約 3.6 秒）より遅い。
- 増えた所：流木（中空の倒木の節穴 2 つ・内壁を暗くする計算）、岩・底床（`solid()` の管の柱の切り抜き）、
  水槽台と濾過槽のメッシュ（`frame` の段階に含む。約 50〜80 ms）。
- 途中、`solid()` が給水管の折れ線（約 36 本の線分）を毎回調べて 1.8 倍近く遅くなっていたのを、縦の柱だけの円柱判定
  （`AquaStand.columnInterior`）に替えて直した。

## 7. 三角形が 47 万 → 約 54 万

- 水槽台・濾過槽の中身・部屋の家具で約 6.5 万（ろ材のかごの格子と、リングろ材の輪が大半）。実機の描画速度は未確認（5. と同じ）。

## 8. 遊びとして決めたこと・割り切り

- 排水口の縁は水面より 0.85 下（カニが遊泳で水面直下まで上がり、渦に吸われて縁を越えられる高さ）。水面の穴は
  漏斗状に落ち込む水面と、水面の描画を円の中で抜くことで表す。遊泳しないで沈むと、管の外側に当たって入れない。
- 給水管には、ポンプ室の床ぎわの吸い込み口から入り、ポンプの流れで水槽へ戻る（ゲーム向けの経路）。
  ポンプの外箱の中を管が通る区間は、外から見るとカニが一瞬隠れる。
- 濾過槽の上縁には幅 0.6 のつばがあり、ろ材かごの階段 → つば → 用品の箱の段 → 台の床 → 開いた扉、で外へ出られる。
