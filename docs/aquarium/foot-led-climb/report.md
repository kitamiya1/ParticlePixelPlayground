# 第 8 段階：接地主導の壁登り・天井への移り

第 7 段階（崖を脚で降りる）の仕組みを、**登る・回り込む**向きへ広げた。床 → 壁・壁 → 天井（・壁 → 床）で、
前の脚が次の面に足場を確保してから胴体が回り始め、胴体の進み具合は「次の面に何本の脚が掛かったか」で止まる。
歩き方「接地主導」（既定）のときだけ働く。「接地 IK（移動は従来）」「従来（歩行周期）」の移動は main と同じ（コードの分岐はすべて `inp.lead`）。

## 結論

- **脚が掛かってから体が移る動きは成立した。** 床から壁へは、前の脚が壁に 2 本（多くは 2〜4 本）掛かり、接地 4 本以上を確かめてから
  張り付く。壁 → 天井は、角では天井の手前で胴体を待たせ、丸い洞窟・倒木の中では体の向きを足先の面から 28° より先へ回さない。
- **体の跳ね・空中のフレーム・面の行き来が大きく減った。** 体の 1 フレームの最大の回転は、垂直の岩で 23.0° → 7.8°、岩の柱で 15.9° → 5.4°、
  掘ったトンネルで 14.7° → 6.5〜10.7°。接地している脚の平均は 9 場面中 8 場面で増え（+0.1〜+2.3 本。倒木の中だけ 4.82 → 4.25）、
  張り付く間の空中のフレームはほぼ 0。ガラスに押し付けたときの床 / 壁の判定の行き来は 35 回 → 0 回、登れない面での行き来は 16 回 → 1 回。
- **悪化した点**：張り付くまで・天井に着くまでが 0.2〜0.9 秒遅い（脚を待つため。意図した動き）。張り出した流木の板のように脚が
  2 本しか掛からない面では、移りが半分で止まり、0.35 秒後から少しずつ進める（詰まりはしないが遅い）。高台の縁を降りた後でカメラの跳ねが
  0.15 → 0.24（カメラの遮蔽の動き。カニの動きは連続）。
- 性能（1 フレームの更新）は main と差がばらつきの範囲（PC 1.36〜1.73 ms / main 1.51〜1.66 ms）。

## 仕組み（脚が接地してから体を移動させる）

`CrabLedge.ts`（FaceHint・FACE・faceCap）・`CrabController.ts`・`CrabFeet.ts`・`CrabRig.ts`・`AquaFootDiag.ts`

1. **次の面の手がかり（FaceHint）**：コントローラが「次の面」の法線・面の上の点・次の面で進む向きを作り、`CrabRig` 経由で脚へ渡す。
   - 床 → 壁（`wallSeek`）：従来の張り付きの条件（登れる急な面へ 0.1 秒押し続ける）を満たしたら。狭い出っ張り（まわりの点の多くが同じ面に
     触れていない）では作らない（小石・岩の角に触れただけで起き上がらない）。この間、壁へ押し込む速さと壁を滑り上がる速さは持たない
     （水中では押し戻しで体が壁を滑り上がり、床から離れて脚が置き直しになっていた）。
   - 壁 → 天井・壁 → 床（凹んだ角）：進む向き（止まっていればスティックの向き）の 0.16 先に、いまの面と 40° 以上向きの違う広い面があれば。
     胴体は次の面から「半径 + 0.05」より近づかない。0.8 秒探しても脚が掛からなければ、従来どおり回り込む（脚の届かない角で詰まらない）。
   - 崖を降り始める道・縁を回り込む道（第 7 段階の `descentPath`・`findMantle`）：道の終わりの面。
2. **脚（CrabFeet）**：先頭の脚（理想の位置が次の面から 0.5 以内）が、理想の位置を次の面へ投影して進む向きへ 0.05〜0.24 ずらした所を、
   面の外 0.2 から面の内向きへ探す（`probeFace`）。面の向きが次の面とそろい（内積 0.5 以上）、壁・天井なら登れる材質（ガラス・管は不可）、
   脚が届く所だけ。同時に運ぶのは 2 本まで（順番に掛ける）・止まっている間はとなりの脚が運んでいれば待つ。掛かった脚は移り終えるまで
   （伸びきり・足場が消えた、の急ぎでなければ）踏み替えない。次の面に掛かった脚の数 `support.next`、接地している足先の組の面
   （Newell の法線）`support.fn` を返す。
3. **胴体（xferMove）**：面の移りの進み具合 p（0 → 1）は、スティックが次の面へ向かっている間だけ、次の面に掛かった脚の数の上限まで進む
   （`faceCap`：1 本 0.2・2 本 0.5・3 本 0.8・4 本 1.0）。体の向きは元の面 → 次の面、体の中心は始め → 次の面の手前を p に合わせて動かす。
   上限で 0.35 秒押し続けたら毎秒 0.8 ずつ上限を上げる（詰まり防止）。スティックを離して 0.4 秒たったら近い方の端へ寄せる（途中の傾いた姿勢で
   止まらない）。逆へ押せば戻り、床からなら床へ戻る（後退で脱出）。接地 2 本未満が 0.4 秒続けば支えを失う（床からなら床へ戻り、壁からは落ちる）。
   道（崖を降り始める・縁を回り込む）も同じ上限で道の進み具合を止める（第 7 段階では一定の速さで進んでいた）。
4. **少しずつ曲がる面**：張り付いている間、体の面を足先の組の面から 28° より先へは回さず、差が 30° を超えると速さを最小 0.25 倍まで落とす。
5. **床 / 壁 / 天井（surf）**：足先の組の面の向き（4 本以上のとき。平滑化）にヒステリシスを付けて決める（床 → 壁 y < 0.45・壁 → 床 > 0.78・
   壁 → 天井 < −0.65・天井 → 壁 > −0.3）。張り付いたまま床へ戻る（歩きへ戻る）のも、足先の面が床（y > 0.5）になってから（最大 0.5 秒待つ）。
6. **隅の接地**：床と壁（ガラスを含む）の隅に押し付けると、押し戻しの向きが床と壁の間になって「空中」扱い → 脚の置き直し、になっていた。
   接地主導では、足元のすぐ下が床なら接地のままにする（縁で脚に支えさせて降りている間は除く）。
7. **診断（?diag・接地の診断）**：次の面に掛かった足先（紫の輪）・次の面の点と法線（紫の線）・「面 床 / 壁 / 天井　壁へ / 天井へ / 道　脚を探す / 移る　
   進み　次の面の脚」を左下に出す。

## 残る問題
1. **張り付くまでが遅い**：脚を待つぶん 0.2〜0.9 秒遅い。脚が 2 本しか掛からない張り出し（陸の流木の板）では、移りが半分で止まってから
   少しずつ進む（2 秒で 1.8〜1.9 進む。main は 2.8〜4.7）。
2. **凸の角（壁の上の縁・流木の側面から裏側）は角として扱っていない**：体の向きを足先の面から 28° 以内に保ち、遅くするだけ。
   丸い倒木の中の天井では、動いている間に接地が 0〜1 本になる瞬間がある（従来も 0〜1 本）。
3. **カメラ**：高台の縁を降りた後・倒木の中で、カメラの遮蔽の動きによる跳ね（0.24・カメラが固体の中 3 フレーム）が main より少し大きい場面がある。
4. **天井を掘って足場を消す**：消えた足場の脚は掴み直すが、その間は接地 0 本の瞬間がある（支えを失うまでの 0.8 秒の間に掴み直すので落ちない）。
5. 数値は同じ入力でも ±数 % 揺れ、前の場面で掘った穴が残ると大きく変わる（新しいページで同じ順番で測った）。iPhone・実際のゲームパッドは未確認。

## ドキュメントとコードの食い違い（見つけたもの）
1. `CrabFeet.ts` の先頭の説明の「上限：高さ ±0.07」は、コード（`bodyPose`）では −0.07〜+0.06（第 7 段階の報告にもあり、未修正）。
2. `ledge_test.js` の「高台の縁から水中へ」の前の説明が 2 行重なっている（「脚が届かない（張り出した岩の下へ沈む縁）」は古い説明）。
3. `feel_test.js` の `feetWalk('平地')` は、名前は平地だが途中で岸の斜面の岩に張り付いて登る（走る・回る速さは登り方で変わる）。
4. 第 7 段階の報告の数値（例：接地主導の低い段差の伸び 1.18・高い崖 1.08）は、main を同じ順番で測り直すと 1.56・1.46 だった
   （同じページで前に走らせた場面の穴・砂山で変わる。報告の値は当時の順番のもの）。
5. `ledge_test.js` の「足場が途中で消える」は低い段差の着地点を掘るので、同じページで後から「低い段差」を測ると結果が変わる（説明に無い）。
6. `CrabController.ts` の先頭の「壁へ向かって押し続けたら CLIMB_GRAB_T で張り付く」は、接地主導では「0.1 秒押して、かつ前の脚が 2 本壁に掛かったら」
   になった（先頭の説明に第 8 段階として追記した）。

（1・2・3・5 はコードを変えていない。）

## 実装の補足
- 面の移りの状態・手がかりは保存しない（瞬間移動・復元で捨てる）。管の中・水槽の外・泳ぐ・掘る・引っ張る間は従来どおり。
- 空中・水中から天井へつかまる（跳んでつかまる）は従来のまま（脚が宙にあるため）。
