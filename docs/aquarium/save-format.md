# 水槽探検：セーブの方式と保存データの仕様

コード：`src/aquarium/AquaSave.ts`（形式・検証・保存先）、`src/aquarium/AquaSaveUi.ts`（自動保存・メニュー）、
`src/aquarium/main.ts`（集める `gather`・起動時の復元）、`DigField.exportPrims / restore`（`AquariumDig.ts`）、
`AquariumDigFx.flushAllAsync`。

## 1. 保存先

| 優先 | 保存先 | 使う条件 | 中身 |
| ---: | --- | --- | --- |
| 1 | IndexedDB（DB `ppp-aquarium`、ストア `saves`） | ふつうのブラウザ（スマホ含む） | 下の `SaveData` を構造化複製のまま（空洞は `Float64Array`） |
| 2 | localStorage（鍵 `ppp-aquarium:<鍵>`） | IndexedDB が開けない（古いブラウザのプライベートモード等）・開くのに 4 秒以上かかる（主スレッドが空いていた時間で数える。重い生成の間は数えない） | 書き出しファイルと同じ JSON 文字列 |
| 3 | メモリ | どちらも使えない・URL に `?nosave`（自動検証用） | 閉じると消える（メニューに「保存しません」と出す） |
| 補 | localStorage（鍵 `ppp-aquarium:journal:<タブ>`） | IndexedDB のとき、ページが隠れる・閉じる直前だけ | 閉じる直前の控え（6 章） |

保存先は起動のたびに選び直す。localStorage へ落ちた起動（メニューと短い知らせで「予備の保存先」を使っていると出す）で保存した進捗は、
次に IndexedDB が開けた起動で引き継ぐ（1.1）。以前の版は互いを見なかったため、その進捗が読まれず、消えたように見えた
（docs/app-packaging/report.md 5.1）。

### 1.1 予備の保存先（localStorage）からの引き継ぎ（`SaveStore.adoptFallback`、2026-11-27）

IndexedDB が開けた起動で、読み込みの前に localStorage の `ppp-aquarium:current`（読めなければ `backup`）を調べる。

| localStorage | IndexedDB の `current` | すること |
| --- | --- | --- |
| 無い・どちらも検証を通らない | — | 何もしない（localStorage にも触れない） |
| 正常 | 同じ識別子（引き継ぎ済み） | localStorage の分を消すだけ |
| 正常 | 無い・読めない | localStorage の進捗を `current` にする（読めない `current` は先に `corrupt-*` へ隔離）。知らせ「予備の保存先の進捗を引き継ぎました」 |
| 正常 | 別の正常な進捗 | **どちらも上書きしない**。`savedAt` が新しい方を `current` にし、もう一方を `alt-<時刻>` に残す（IndexedDB の方を残すときは `current` を書き換えるのと同じトランザクションで。`backup` にも回る）。知らせとメニューの説明を出す |

- IndexedDB へ書けてから（トランザクションの完了）localStorage の `current` / `backup` を消す。読めなかった localStorage の `current` は消す前に `corrupt-*` へ写す。
- 書くときは `current` の識別子を比べる（5 章）。その間にほかのタブが `current` を進めていたら何もせず、localStorage の分も残す（次の起動でもう一度）。
- `alt-*` は最大 3 個（古い順に消す。同じ識別子は足さない）。メニューの「残したもう一方の進捗を書き出す」（書き出したら消す）と
  「もう一方の進捗に切り替える」（いまの進捗を保存してから `alt` に残し、置き換えて読み込み直す。どちらも消えない）。
- 確認：`docs/aquarium/tools/save_fallback_test.js`（F1〜F6。8 章の後の表）。

IndexedDB を選んだ理由：掘った空洞は最大 6000 個 × 7 個の数（倍精度で 336 KB）。JSON 化せずに型付き配列のまま入れられ、
書き込みは非同期で画面を止めない（2955 個・166 KB で書き込み 1.6 ms、集める処理 0.8 ms）。localStorage は 5 MB 程度の上限と
同期の書き込み（画面が止まる）があるので予備にだけ使う。

### 鍵

| 鍵 | 意味 |
| --- | --- |
| `current` | いまの進捗（世代 `rev` と更新の識別子 `saveId` 付き） |
| `backup` | 1 つ前の正常なデータ。`current` が正常と分かっているとき（読めた・自分で書いた・置き換えのときは検証を通るとき）だけ、書く前に `current` をここへ写す（1 つのトランザクション） |
| `corrupt-<時刻>` | 読めなかったデータの隔離（最大 3 個。古い順に消す） |
| `alt-<時刻>-<乱数>` | 予備の保存先からの引き継ぎで `current` にしなかった方の正常な進捗（最大 3 個。1.1） |

## 2. 読み込みの流れ（起動時）

1. 重い生成（地形・植物）と並行して保存先を開く。
2. `current` を読む。無ければ初期状態（`empty`）。
3. `validateSave` を通れば使う（`ok`）。知らない場所・仲間の id は捨てて警告にする。
4. 通らなければ `current` を `corrupt-*` へ隔離し（`current` 自体は消さない）、`backup` を検証する。通れば `backup` から再開（`recovered`）。
5. どちらも読めなければ初期状態で始める（`corrupt`）。どちらの場合もメニューに理由を出し、短い知らせを出す。
6. 復元：`DigField.restore(prims)`（掘ったときと同じ `add` を通す）→ `AquariumDigFx.flushAllAsync`（全区画を作り直してから
   1 回で差し替え、同じ瞬間に当たり判定へ入れる）→ 訪れた場所 → プレイヤー（保存した位置が固体の中ならスタート地点）→ 仲間。
   これらは最初のフレームより前に済む。掘った区画が多いときは読み込み画面に「掘った穴を復元しています… n / 全体 区画」と出る。

`recovered` / `corrupt` のあとは `current` を正常と見なさないので、最初の自動保存は `backup` を上書きしない。

読む前に、閉じる直前の控え（6 章）を調べる：控えの元にした `current` のままなら控えから再開する。

## 3. 書き込み（自動保存）

| きっかけ | いつ書くか |
| --- | --- |
| 掘った（かき出しの回数が変わった） | 最初の変化から 2 秒後、かつ前の保存から 4 秒以上（掘っている間に何度も書かない） |
| 大事な出来事（仲間になった・調べた・モード・初めての場所・控えから再開） | 0.3 秒後（前の保存から 1 秒以上） |
| 動いただけ（0.5 以上） | 15 秒ごと |
| ページが隠れる・閉じる（`visibilitychange` / `pagehide`） | 未保存の変化があれば、同期の控えを書いてからすぐ（非同期の書き込みは終わらないことがある：6 章） |
| メニューの「今すぐ保存」 | すぐ（書いている途中なら、終わってからもう一度） |
| 書けなかった | 知らせ（続けて失敗している間は 1 回）。間を 8〜30 秒に広げて書き直す |

どの書き込みも、世代を 1 増やし、新しい識別子を付け、`current` の識別子が「このタブが最後に読んだ / 書いた値」と同じときだけ書く（5 章）。

## 4. 形式（version 2。2026-11-26 の M2 から。version 1 は読み込むときに migrate で 2 へ直す）

```ts
interface SaveData {
  format: 'ppp-aquarium-save';
  version: 2;
  created: number;            // 最初に作った時刻（ms）
  savedAt: number;            // 最後に保存した時刻（ms）
  playTime: number;           // 遊んだ秒数
  rev: number;                // 保存の世代（書くたびに 1 増える。無い古いデータは 0）
  saveId: string;             // 更新の識別子（書くたびに新しい値。複数タブの競合の判定）
  player: { tank: 'home'; x; y; z; heading; camera: 'adventure' | 'observe' | 'diorama';
            sand: number;           // 手持ちの砂（体積。0〜SAND.capacity = 4。画面の 1 杯 = 0.05）
            tool: 'dig' | 'fill' }; // いまの道具（掘る / 盛る）
  progress: {
    visited: string[];        // 訪れた場所の id（AquariumSpots）
    flags: Record<string, boolean>; // イベントの進み（例：'burrow.examined'）
  };
  tanks: {                    // 水槽ごと（将来の隣の水槽は別の鍵）
    home: { dig: { prims: Float64Array } };  // 編集 1 個 = [ax, ay, az, bx, by, bz, r, 種類]。種類 0 = 掘った空洞・1 = 盛った砂。編集した順
  };
  buddies: {
    id: string; species: string;
    found: boolean;           // 引っこ抜いて仲間になった
    mode: 'free' | 'follow';
    tank: 'home'; x; y; z;
    home: [x, z];             // 自由生活の住みか
    traits: Record<string, number | string>; // 個体の特徴（将来の繁殖・レア）
  }[];
}
```

ゴカイ（2026-11-28）も `buddies` に入れる（保存の版は 2 のまま。古い版のゲームは知らない id として捨てて警告するだけ）：

| 項目 | ゴカイでの意味 |
| --- | --- |
| `id` / `species` | `gokai-0`〜`gokai-2` / `'gokai'` |
| `found` | 一度でも引っこ抜いた（名前が分かる） |
| `mode` | 使わない（いつも `'free'`） |
| `x, y, z` | 砂の中なら巣穴の口、外なら頭の位置 |
| `home` | 最初の巣穴の口（戻れないときの戻り先） |
| `traits` | `len`（体長 m）・`thick`（太さの倍率）・`tone`（体色 0 = 赤褐色〜1 = 淡いピンク）・`seed`（模様）・`state`（`'buried'` / `'free'`）・`yaw`（頭の向き） |

読み込みでは地形（掘った穴・盛った砂）を戻した後に置き直す。砂の中だった個体は同じ口から巣穴を作り直し（作れなければ住みか）、
外だった個体は同じ位置・向きで地面に置く（固体の中・水の外なら住みか）。個体差が保存と違えば、保存の値で作り直す。

### 検証（`validateSave`）

- 形：`format` が違う・`version` が新しい / 古い / 範囲外 → 拒否（新しい版は「ページを更新してください」）。
- 数：有限でない値（NaN・Infinity）→ 拒否。
- 範囲：プレイヤーは部屋の中、空洞の両端と仲間は水槽の外接箱 + 1.5 の中、空洞の太さは 0.01〜`DIG.rMax`、
  空洞の数は `DIG.maxPrims` 以下 → 外れたら拒否。
- id：知らない場所・仲間・水槽は捨てて警告。同じ仲間が 2 つ → 拒否。
- 拒否したデータはゲームへ一切渡さない（部分的に読み込まない）。

### 書き出しファイル（JSON）

`SaveData` と同じ形で、空洞だけ `{ "f64": "<base64>" }`（倍精度・リトルエンディアン）にする。読み込むときは同じ検証を通し、
通ったら `current` に書いて（いまの `current` は `backup` へ）ページを読み込み直す（起動時と同じ復元の道を通す）。
検証を通らないファイルでは保存データに触れない。ファイル名は `aquarium-save-YYYYMMDD-HHMM.json`。

### 版を上げるとき

`migrate()` に「前の版 → 新しい版」の変換を足し、`SAVE_VERSION` を上げる。追加予定の場所：

| 追加するもの | 置き場所 |
| --- | --- |
| 盛った砂（M2・済み） | `tanks[id].dig.prims` の 8 個目の数（種類）。空洞と同じ並びに編集した順で入れる（下の「版 2」） |
| 植物（M3） | `tanks[id].plants` |
| 生き物の個体・繁殖（M4） | `buddies[].traits`、または `tanks[id].creatures` |
| 隣の水槽（M5） | `tanks` の別の鍵、`player.tank` |

### 版 2（M2：盛った砂・手持ちの砂）

- **掘った空洞と盛った砂を 1 つの並びに、編集した順で入れる**（別々の並びにしない）。地形は「元の砂 → 編集を順に当てる」で決まり
  （`AquariumDig.ts` の先頭の説明：同じ種類が続く間を 1 つの層にまとめ、掘った層は削る・盛った層は足す）、順序が変わると
  「先に掘った穴へ盛った砂」と「盛った砂を掘った穴」が入れ替わってしまうため。復元は掘ったときと同じ `add` を順に通すので、
  層の番号・区画の登録・版（live / snap）は遊んでいたときと同じになる。
- 検証：並びの長さが 8 の倍数、種類は 0 か 1（それ以外は全体を拒否）、半径は 0.01〜`DIG.rMax`（盛った砂は最大 `FILL.rMax` = 0.56。第 10 段階から盛った砂は横に伸びたカプセル（a ≠ b）にもなる）、
  両端は水槽の外接箱 + 1.5 の中、数は `DIG.maxPrims` 以下（掘った空洞と合わせて）。
  `player.sand` は 0 以上の数（`SaveContext.sandCap` の 4 倍を超えれば拒否、少し超える分は丸める。第 10 段階から持てる量の上限は無く、`sandCap` は検証用の `SAND.maxStore` = 100000。
  読み込んだ後、手持ちが地形から数えた「掘った − 盛った」より少なければ差を戻す（以前の容量 4 で捨てた砂の救済。保存の形は変えない）、`player.tool` は `'fill'` 以外を `'dig'` に。
- **版 1 → 2 の移行（`migrate`）**：空洞の並び（7 個ずつ）に種類 0 を足して 8 個ずつにし、`player` に `sand: 0`・`tool: 'dig'` を足す。
  元のデータは書き換えない（写しを変換）。並びの長さが 7 の倍数でない版 1 は変換せずに拒否させる。版 1 には盛った砂が無いので、
  合成の結果は版 1 のページで掘ったときと同じ値になる（下の確認）。IndexedDB・localStorage の予備・控え・書き出しファイルのどれも
  読み込むときに同じ `validateSave`（中で `migrate`）を通るので、どこに残った版 1 も読める。次に書くときは版 2 で書く
  （`current` が正常な版 1 なら、それが `backup` へ回る）。
- 版 1 のページ（古いタブ）が版 2 のデータを読むと「新しい版（2）の保存データです。ページを更新してください」で拒否する（上書きしない）。
- 盛った・掘った砂の量（手持ちの砂の増減）はフレームに分けて測るので、保存の直前に測り終えてから集める（`gather`）。

## 5. 複数のタブ（競合）

- タブは「最後に読んだ / 書いた `current` の識別子」を覚える（識別子の無い古いデータ・壊れたデータは内容から作った値。`saveToken`）。
- 書くときは 1 つの IndexedDB の readwrite トランザクションの中で `current` を読み、識別子が同じときだけ `backup` へ回して書く。
  違えば何も書かずに終える（比べて書く）。同じストアの readwrite のトランザクションは順に実行されるので、読んだ値と書く判断の間に
  ほかのタブの書き込みは入らない。localStorage の予備は同期の API で同じことをする。
- 違った（ほかのタブが進めた・初期状態に戻した）タブは「競合」：このタブからは書かない。画面の上に知らせを出し続け、
  「このタブの進捗を書き出す」「最新の進捗を読み込む」を出す。セーブのボタンの印が赤くなる。
- 書いたタブは BroadcastChannel（`ppp-aquarium-save`）で知らせ、ほかのタブは次に書く前に競合になる。タブへ戻ったときも確かめる。
- 初期状態に戻す・ファイルの読み込みは明示した置き換えなので比べない（いまの `current` は検証を通るときだけ `backup` へ）。

## 6. 閉じる直前の控えと、ブラウザが保証しないこと

IndexedDB の書き込みは非同期で、ページが隠れた・閉じられた直後にブラウザがページを止めると終わらないことがある
（Chromium の再読み込みで確かめたところ、閉じる直前に始めた書き込みは毎回入っていなかった。iPhone の Safari でアプリを切り替えた
直後も同じことが起こりうる）。そこで：

1. ページが隠れる・閉じるとき、未保存の変化があれば、同期の API（localStorage、鍵 `ppp-aquarium:journal:<タブ>`）へ控えを書く。
   控えには「元にした `current` の識別子」（書いている途中の保存の識別子も）を入れる。続けて IndexedDB へ書き、書けたら控えを消す。
2. 次に開いたとき、控えの元にした識別子が今の `current` と同じなら、控えの方が新しいので控えから再開し、すぐ保存先へ書く。
3. 違えば（ほかのタブがその後に保存した）使わず、`ppp-aquarium:journal-orphan` に残してメニューの「使わなかった進捗を書き出す」で出せる。

ブラウザが保証しないこと（メニューにも書いた）：控えの同期の書き込みも、ブラウザがページを止める前に終わる保証は無い（終わりやすい、まで）。
iPhone・iPad の Safari は、しばらく（目安 7 日）開かなかったサイトの保存データを消すことがある。プライベートブラウズでは閉じると消える。
メニューの「消されにくくする」は `navigator.storage.persist()` をブラウザに頼むだけで、断られることがある。大事な進捗は書き出す。

## 7. 初期状態に戻す

メニューの「初期状態に戻す…」→ 説明を読んで「本当に戻す」の 2 段。`current` を `backup` へ写してから消し、読み込み直す。
次の起動は初期状態（`empty`。`backup` からは戻さない）。1 つ前のデータは `backup` に 1 回分だけ残る。

## 8. 確認したこと（2026-11-25、開発サーバー、`docs/aquarium/tools/save_helpers.js`・`save_conflict_test.js`）

複数タブ・控え・保存の失敗の確認は `save-first-buddy/report.md` の 6.3。

| 項目 | 結果 |
| --- | --- |
| 岸辺のトンネル + 左・奥のガラス際の巣穴（空洞 34・区画 49）を保存 → 読み込み直し | 空洞の値・区画ごとの三角形の数と頂点・当たり判定の値・隠した植物/小石・カニの位置・訪れた場所がすべて一致 |
| 大量の掘削（空洞 2955・区画 610、水槽の 85%） | 保存 166 KB・書き込み 1.6 ms。読み込み直しで完全に一致。復元の作り直しは約 5.5 秒（読み込み画面に進み具合） |
| 壊れたデータ（文字列・NaN・版 99・水槽の外の空洞・current と backup の両方） | どれも起動でき、隔離した上で backup から再開 / 初期状態。正常な backup は残る |
| 書き出し → 読み込みの往復 | 空洞の値が一致。壊れたファイル（途中で切れた JSON・版 0・base64 の破損）は拒否、知らない場所は警告だけ |
| 初期状態に戻す（画面のボタン） | 確認のあと読み込み直して初期状態。`backup` に前のデータが残る |
