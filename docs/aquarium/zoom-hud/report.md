# 第 1 段階：ページの拡大からの復旧と HUD の縮小 — 報告

ブランチ：`fix/aquarium-zoom-hud`（`main` = `f6e0e29` から）。検証は Chromium（Playwright）のスマホの模擬（390×844 / 844×390・タッチ・isMobile）と
PC（1280×800）。**iPhone Safari の実機では確かめていない**（6 章）。

## 1. 実機の報告から分かったこと・考えた原因

| 報告 | コードから分かること |
|---|---|
| 「元に戻す」で戻らない | `tryReset()` は viewport の設定を一瞬 `maximum-scale=1` にするだけ。iOS は `maximum-scale` を無視することが多く、効かない環境がある。以前の版は 1 回だけ測り、その前に `check()` が一瞬 1 に戻った値を見ると知らせを消していた（成功したように見える余地があった） |
| 「保存して読み込み直す」で戻らない | `location.reload()` だった。Safari（WebKit）は同じ履歴の項目の読み込み直しで、前のスクロールと**倍率**を戻す（履歴の項目が倍率を覚えている）。読み込み直しでは戻らないのはこの仕組みと合う（実機の動作から推定。WebKit の実装の挙動で、仕様ではない） |
| 拡大が起きる経路 | 前回の診断（最大 2.17 倍）でも経路は不明。候補：①ゲームの面の上のピンチで touch-action の領域が古い一瞬、②ボタン・欄の外のダブルタップ、③欄の上から始めたピンチ（前回止めた）。今回 ①② を WebKit のタッチ端末で追加で止め、記録を残すようにした |

## 2. 実装（`src/aquarium/AquaViewport.ts`、`main.ts`、`aquarium.css`、`src/game/Input.ts`、`src/ui/TouchControls.ts`）

| 要件 | 実装 |
|---|---|
| 拡大を防ぐ | 従来（gesturestart/change を止める・欄の外から始めた 2 本指の touchmove を止める・欄は pan-y）に加え、**WebKit のタッチ端末だけ**：ゲームの面の上の 2 本指の touchmove も止める、ボタン・欄の外の素早い 2 回目の touchend（ダブルタップの拡大）を止める。Chromium の動作は変えていない（合成ピンチでカメラのズームが効かなくなる例があったため） |
| 拡大中も見失わない | 倍率が 1.02 倍を超えている間、`body` 全体を見えている範囲（visual viewport）へ `translate + scale(1/倍率)` で置き直す（`html.aqua-pinned`）。知らせと ?diag は `body` の外（`html` の直下）へ移した。指の動きは倍率の分だけ小さく届くので `Input.pointerScale` で戻す（スティック・掘るの照準・挟むボタンの視点・画面のドラッグ）。Canvas の描画の大きさは `clientWidth/Height`（変換の影響を受けない）で測るように変えた |
| 「元に戻す」が失敗したら成功と出さない | 0.3 / 0.7 / 1.2 秒の 3 回測り、すべて 1.02 倍以下のときだけ「✓ 倍率が戻りました」。測っている間は知らせを消さない。1 回でも残れば「✗ 戻せませんでした（いまの倍率）」とボタン「もう一度 元に戻す」 |
| 現実的な復旧手段 | 「保存して開き直す」：保存できたときだけ `location.replace(今の URL + ?reopen=時刻)`（読み込み直しではなく新しく開く）。「保存して新しいタブで開く」：押した瞬間にタブを開き（ポップアップとして止められないため）、保存できたらそこへ移る。前のタブは保存をやめる（`AutoSaver.suspended`。2 つのタブの競合を防ぐ）。開けなければ「✗ 新しいタブを開けませんでした」。「このまま遊ぶ」：知らせを閉じ、上に「画面が拡大中（×倍率）— 直す」だけを残す |
| 保存・開き直しの成否の表示 | 知らせに結果の行（✓ 保存しました（時刻）・✗ 保存できなかったため開き直していません 等）と保存の状態（保存済み／未保存／失敗／競合／保存しない）。保存できない状態では 1 回目は開き直さず、2 回目で保存せずに開き直す（前回の仕組みを開き直しにも使う）。開き直した先では 0.9 秒後に倍率を測り「開き直しました：倍率 ×1.00（正常）」または「✗ 開き直しても拡大が残っています」 |
| 診断 | 拡大が始まった・終わった（続いた秒数）・知らせ・元に戻す（前後の倍率）・開き直す・開き直した後・回転の後も拡大、を時刻・倍率・比（レイアウトの幅 ÷ 見えている幅）・向き・visual / layout / inner の大きさ・直前の指（本数・要素・座標）と一緒に `localStorage` の `ppp-aquarium:vplog`（最大 40 件）へ。HUD の「詳細」で見られ、「記録をコピー」「記録を消す」。?diag の表示も従来どおり（置き直し中・座標の倍・ダブルタップを止めた数を追加） |

倍率の判定は `visualViewport.scale` と「レイアウトの幅 ÷ 見えている幅」の大きい方（片方が正しく報告されない場合に備える）。

## 5. 文書とコードの食い違い（気づいたもの）

- 前回の報告の「`zoom_test` A2：3.20 → 1.40 → 3.14」は、説明の欄が開いたままだと指が欄に落ちて再現しない（今回の変更の前からの配置。
  説明を閉じると同じ値）。

- 前回の報告の 2 章は「保存して読み込み直す」で倍率が戻るかを未確認としていた。実機では戻らなかった（今回の依頼）。

## 6. iPhone の実機でしか確かめられないこと（公開後の確認事項）

1. ふだんの遊び方で拡大が起きなくなったか（詳細の「拡大 n 回」が 0 のままか）。起きたら「記録をコピー」で記録を送ってもらう
2. **ゲームの面の上の 2 本指の touchmove を止めても、カメラのズーム（2 本指）・スティック + 視点が効くか**（WebKit ではポインターの通知が先に届くので効く見込み。効かなければこの変更が原因）
3. ボタン・欄の外のダブルタップで拡大しないか。ボタン（メニュー・知らせ・説明の ×）が今までどおり押せるか
4. 拡大されたとき：ゲームの画面が見えている範囲に収まるか、スティック・ボタンが指どおりに効くか（`pointerScale`）
5. 「元に戻す」：戻らなければ「✗」と出るか（成功と出ないか）
6. 「保存して開き直す」で倍率が戻るか（`location.replace`。戻らなければ記録に「開き直した後：拡大が残る」）
7. 「保存して新しいタブで開く」で新しいタブが開くか（ポップアップとして止められないか）、新しいタブで進捗が続くか、前のタブで競合の知らせが出ても進捗が失われないか
8. 詳細の欄の開閉・スクロール・「記録をコピー」（クリップボード）が縦・横で使えるか

## 7. 残る問題

- 拡大の経路は実機で特定できていない。今回の防ぐ仕組みは推定に基づく（1 章）。
- 「元に戻す」は iOS では効かない見込みが高い（効かないことを正しく出すようにした）。
- 新しいタブの方式では、前のタブを閉じるのは利用者に任せる（スクリプトからは閉じられない）。
