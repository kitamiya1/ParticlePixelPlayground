# 第 3 段階：引っこ抜きの演出・効果音・ゲームパッド・左のハサミ — 報告

ブランチ：`feat/aquarium-pop-sfx-gamepad`（`main` = `7be9972`、第 2 段階のマージの後から）。検証は Chromium（Playwright）。
**ゲームパッドは本物ではなく模擬（`navigator.getGamepads` の置き換え）**、**iPhone の実機・実際の音の聞こえ方は確かめていない**（5 章）。

## 1. 引っこ抜きの演出と効果音

| 要件 | 実装 |
|---|---|
| 引っ張っている間の砂のこすれる音・踏ん張る音 | `AquaAudio.setTug`：ループのノイズを帯域フィルターに通した「こすれ」（張力・縁のこすれ・引き出しの速さで大きく）＋のこぎり波を低域に通した「唸り」（張力 0.45 を越えると鳴る）。生き物が引き戻すたびに短い「ぐっ」（`grunt`、段階で強く）と泡（`bubble`） |
| 張力で音が変わる | こすれの帯域の中心 380 → 1880 Hz（張力・暴れる強さで明るく）、唸りの音程 58 → 128 Hz |
| 「スポン！」 | `AquaAudio.pop`：栓が抜けるような短い破裂のノイズ（2.4 kHz）＋高い音から一気に下がる「ポン」（1350 → 170 Hz、0.13 秒）＋低い「ドン」＋遅れて泡の粒 4 つ |
| 抜けた直後の砂粒・泡・短い衝撃 | 砂の崩れ 12 → 18 粒、泡の柱 12、砂煙。「スポン！」の文字（穴の上 0.35、0.9 秒で消える）と広がる衝撃の輪。0.07 秒だけ時間を 1/4 に（ヒットストップ） |
| 勢い余って転ぶ | 従来の `crab.tumble`（張力に応じた勢いで後ろへ転ぶ・0.9 秒）とカメラの反動をそのまま使う |
| 抜けたことが一目で伝わる | スナモグリが抜けた勢いで**後ろへ 1 回宙返り**して着地（`AquaBuddy.updateFlying`。抜けた瞬間の体の起こし具合から回り始め、落ちるまでの見込みの時間で水平に）、宙で手足をばたつかせる |
| 見失わない | カメラの揺れは従来のまま、文字は穴より上にずらし短く、輪は 0.55 秒で消える |
| オリジナルの音 | 音の素材ファイルは使わず、すべて Web Audio API で合成 |
| 音量・ミュート | 右上の「🔊 / 🔇」→ 欄：消音のチェック・音量（0〜100）・「試しに鳴らす（スポン）」。`localStorage`（`ppp-aquarium:audio`）に覚える |
| iPhone Safari | AudioContext は最初の利用者の操作（pointerdown / pointerup / touchend / click / keydown）の中で作って `resume` し、無音の短い音を鳴らす。裏へ回ったら `suspend`、戻ったら次の操作で `resume`。欄の入力の文字は 16 px（Safari のフォーカス時の拡大を避ける） |

ほかに：挟んだ・離したときの小さな「カチッ」、滑ったときのきしむ音。

## 2. ゲームパッドと左のハサミ

割り当て（`src/aquarium/AquaGamepad.ts`。standard の配列。Xbox / PlayStation の名前）：

| 入力 | 操作 |
|---|---|
| 左スティック | 移動 |
| 右スティック | 両方のハサミ（腕）の向き。X / □ で掘っている間は掘る向きの照準 |
| LT / L2・RT / R2 | 左・右のハサミを閉じる（押している間。0.35 で閉じ 0.2 で開く） |
| A / ×・B / ○ | ジャンプ・ダッシュ |
| X / □・Y / △ | 掘る / 盛る（押している間）・掘る ↔ 盛る |
| RB / R1 | カメラの切り替え |
| LB / L1 + 右スティック・十字キー | カメラを回す・ズーム |
| 右スティック押し込み | カメラをカニの後ろへ |
| Back / Share・Start / Options | 仲間を呼ぶ・操作の説明 |

- 遊び：スティックは半径 0.18 の円形のデッドゾーン（外側を 0〜1 に広げ直す）。
- 接続・切断の知らせ、切断・裏へ回ったときは押している物をすべて離す。複数つないだときは最後に操作したもの。標準でない配列は同じ番号で読み、
  知らせで「ボタンの位置が違うことがある」と出す。詳細の欄にパッドの名前・左右のハサミの状態を出す。
- 左のハサミ：`CrabRig` に右と同じ構え・IK（減衰付き最小二乗）を左右反転して追加（`gripL`・`anchorL`・`pinchL`・`left`）。
  `GrabSystem` の 2 本目（`grabL`。腕の届く長さは鋏の大きさの比で 0.27）。2 本の鋏で同じ物・生き物は挟まない
  （挟んでいる物と、挟もうとしている途中の物も除く）。物の時間は 2 本で 1 回だけ進める（`PropSystem.updateMany`、
  `GrabSystem.pre` / `post` に分けた）。カニへの手応えは 2 本の和（速さの上限は小さい方）。左のハサミでも巣穴の触角を挟んで引っ張れる
  （引っ張りの印・音も同じ）。
- スマホ・PC は従来どおり右のハサミだけ（スマホの切り替えスイッチ・PC の E）。PC の E は右トリガーと同じ扱い。

## 4. 文書とコードの食い違い・残る問題

- 第 2 段階までの `GrabSystem.update` は物の時間も進めていた。今回 `pre`（状態）・`PropSystem.updateMany`（物）・`post`（手応え）に分け、
  `update` は 1 本だけのときの近道として残した（main は 2 本の形を使う）。`PropSystem.update` も `updateMany` の近道として残した。
- PC・スマホで左のハサミを使う操作は無い（ゲームパッドだけ）。
- 音は Chromium で例外なく鳴らせることだけ確かめた。聞こえ方（大きさの釣り合い・不快でないか）は人の耳で確かめていない。
- 本物のゲームパッドでは確かめていない（模擬のパッドだけ）。機種ごとのボタンの配置（標準でない配列）は同じ番号で読むだけ。

## 5. 実機でしか確かめられないこと（公開後の確認事項）

1. iPhone Safari：最初に画面に触れた後に音が鳴るか（消音スイッチが切れている状態で）、アプリの切り替え後も鳴るか、音量・消音の欄
2. 引っ張っている間の音・「スポン！」の聞こえ方と大きさの釣り合い、演出の強さ（見失わないか、ヒットストップの違和感）
3. 本物のゲームパッド（Xbox / DualSense / Switch Pro 等）：接続・切断の知らせ、ボタンの配置、トリガーの効き、右スティックの腕の動き、
   iPhone・iPad の Safari でパッドが使えるか
4. 左右のハサミで物を持ったときの見た目（左の鋏が物を挟んで見えるか）
