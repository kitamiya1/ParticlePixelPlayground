## 1. 地形の見た目と当たり判定の食い違い

### 検査の方法（`docs/aquarium/tools/mesh_check.js`）

`mesh_config.json` の 9 つの掘り方（水平・曲げる・斜め上・照準の上下左右）でトンネルを掘り、全区画を作り直してから、
カニが通った道（空洞の中、約 440 点）から全方向へ光線を約 4 万本飛ばし、見えている三角形と砂の距離関数（`sandSolid`）を比べる。
`miss` = 距離関数では壁があるのに三角形に当たらない、`late` = 三角形がずっと奥、`back` = 裏面に先に当たる。

### 原因

不一致の光線の、距離関数の値を光線に沿って並べると、どれも **正 → わずかに負（−0.002〜−0.025）→ 正** だった。
当たった点は元の地表から 0.03〜0.12 下、空洞の表面のすぐ外（空洞の値 ≈ 0）。つまり：

1. **トンネルの天井と元の地表の間に残る、格子より薄い砂の膜**（主な原因。斜め上へ掘った所・地表すれすれの所）。
   掘った後の砂は `smax(地表の距離, −空洞, 0.12)` で、天井が地表に近づくと、その間に深さ 0.01〜0.03 の膜が残る。
   Surface Nets（格子 0.1）の格子点には負の値が現れないので三角形にならず、**見た目は穴が開いているのに、当たり判定には
   見えない膜が残る**（カニ・カメラが見えない膜の上を歩く・止まる）。
2. **空洞どうしの継ぎ目の稜線**（曲がったトンネル・掘り足した所）。継ぎ目の丸み（`unionK` 0.08）が格子より小さく、
   砂が空洞側へ尖った稜線を Surface Nets は頂点の平均で丸めるので、三角形が距離関数より 0.01〜0.03 内側になり、
   かすめる向きの光線が抜けた。
3. **空洞の縁で値がほぼ 0 の所**（地表と空洞の丸みが重なる所）にも、深さ 0.001〜0.02 の膜が広く残っていた
   （検査で「厚さ 0.12 未満」として除いていた光線の多く。こちらも見えない膜）。
4. 検査側の誤り：水槽の外（ガラスの向こう、z > 10）の砂に当たった光線を数えていた（高さ場を縁で延ばした値。砂は描かない）。

区画の作り直しの漏れ・`snap` / `live` の版のずれ・三角形の表裏ではなかった（全区画を作り直しても数が変わらない、`back` = 0）。

### 修正（`src/aquarium/AquariumDig.ts`）

- **薄い膜を開ける**：掘った後の砂の値に `(FILM + d − c) / 2`（`FILM` = 0.2）を `max` で加えた（`carveSand`）。
  空洞と元の地表の間の膜の厚さ（c − d）が 0.2 より薄い所は、当たり判定でも見た目（`meshValue`）でも同じ式で開く。
  膜でない所（空洞の中・地表より上・厚い砂）では符号は変わらない。傾きは 1 以下なので距離の下限のまま。
- **継ぎ目を格子に見合うだけ丸める**：`unionK` 0.08 → 0.2（`carve` が外接箱から 0.3 より離れた空洞を箱の距離で済ませるので 0.3 未満）。
- **空洞の近くの極薄の膜を消す**：空洞の値 c < 0.25 の所だけ、砂の値を最大 0.03 正へずらす（`SHAVE`。c ≥ 0.25 では 0 なので、
  作り直さない区画の高さ場の網とはずれない）。
- 検査：水槽の外に当たる光線を除外。区画の作り直しの時間の上限を外す `budget` 設定を追加（実時間に左右されず毎回同じ結果になる）。

### 結果

| 変更前（`5e85b1b`）1 回目 | 38,790 | 11 | miss 11 | 309 |

連続的に開けるため、しきい値の直前の膜は距離関数の値が −0.01 程度しかなく、Surface Nets の三角形が距離関数より薄く（最大 0.2）

  **接地していても進もうとしている向きへほとんど進めないとき**にも働くようにした（`CrabController.ts`）。

## 2. 地下の入口のカメラ

### 原因

岸の斜面のトンネルは地表から斜め下の坂で始まるので、カニが坂へ入った瞬間に

- 後ろの坂の床で「床」と判定され、仰角の下限が −2 → 0.49 に跳ねる
- 同時に腕（注視点 → カメラ）が溝の縁・入口の上の砂に当たって 3.2 → 0.7 に縮む（寄る速さ 9/秒の指数で、大きく縮むと 1 フレームに 0.4）
- 近い視点（`near`）への切り替えは「頭の上に砂の天井があること」が条件なので、坂の途中では始まらず遅れる

が 0.3 秒ほどの間に重なり、カメラが急に寄っていた。横から見ていると、めり込み防止の安全網が手前へ一気に戻していた。

### 修正（`src/aquarium/AquaCamera.ts`。掘った穴のそば `digNear` だけ。それ以外の場所の振る舞いは変えない）

- **先読み**（`LEAD` = 0.35 秒）：カニの進む先（いまの速度、接地中は進む先の床の高さに合わせる）でも、床・天井・腕の長さ・
  地下の度合いを調べ、厳しい方を使う。同じ動きを先に始めて長い時間に分ける。
- **寄る速さの上限**（`CLOSE_SPEED` = 3.5/秒）：いまの距離のカメラの位置がまだ固体から離れている間だけ。
- **位置の動きの上限**（`smoothPose`）：最終的なカメラの位置を「直前の位置 + カニの動き」から 1 秒あたり 4.5（カニが砂に
  隠れている間は 9）までにする。見る向きは変えない（注視点も同じだけ動かす）。制限した位置が固体に近いときは、
  求めた位置の側へ固体から離れる最初の所まで進める（地形の中・裏側を見せない）。**視点を操作している間は制限しない**
  （プレイヤーの yaw / pitch はどこでも変えない）。

### 結果（`docs/aquarium/tools/cam_entry_test.js`：岸の斜面の穴へ地上から歩いて入る 4 秒 → 出る 4 秒 → 再進入 4 秒）

1 フレームのカメラの位置の最大の動き（カニ自身の歩きは 1 フレーム約 0.038）と、カメラとカニの距離の変化の速さの最大：

## 3. 移動と掘る向きを別々に

### 変更前の実装

掘っている間は、移動の向きが掘る向きに置き換えられ（スティックの強さで掘る向きへ進むだけ）、さらに掘る向きの基準が
スティックの向きへ回り込んでいた。カメラ基準のスティックの向きが基準を回すので、カメラを回すと掘る向きも回っていた。

### 変更後（`src/aquarium/CrabController.ts`）

- 掘る向き = 押したときの体の向き（押している間は変えない）+ 照準の左右（最大 ±90°）。上下は照準の上下（従来どおり）。
- 移動 = 左のスティック（ふだんと同じカメラ基準の向き）。掘っている間は速さの上限 1.1（従来と同じ）。掘る向きへは引き寄せない。
- 体の正面（鋏の側）は掘る向きへ回す（従来どおり）。説明文（`main.ts` の操作の説明）も更新。

### 結果

ゲームの処理での検査（`dig_independence_test.js`。動いた向きはカメラ基準：前 = 0、右 = +1.57）：

| 操作 | 変更前 | 変更後 |
| --- | --- | --- |
| A 上を掘りながら前へ | 前へ 2.08、仰角 0.67 | 同じ（前へ 2.08、仰角 0.67） |
| B 右を掘りながら左へ | **前へ**進み（0.06）、掘る向きが 1.29 rad 左へ流れる | **左へ**（−1.59）2.02、掘る向きは右のまま（変化 0） |
| C その場で向きだけ（照準 左 → 右） | 動かず 180° 回る | 同じ |
| D 掘りながらカメラを 1.5 rad 回す | 掘る向き・体の向き 変化 0 | 同じ |
| E カメラを回しながらスティック前 | **掘る向きが 1.44 rad 回る** | 掘る向き 変化 0（移動はカメラ基準） |

スマホの実際のタッチ（CDP のタッチで、スティックと掘るボタンを同時に押す。`touch_independence_test.js`）：
変更後は「上を掘りながら前へ」= 前へ 0.93・仰角 1.05、「右を掘りながら左へ」= 左へ（−1.57）0.93・掘る向き右（−1.57）、
「その場で向きだけ」= 動かず ±1.57。変更前は「右を掘りながら左へ」で前へ進み、掘る向きは正面のままだった。
離したあとに掘る・移動・照準が残らないことも確認。

## 5. 残っている問題

1. **開口部の縁の不一致 2〜4 本 / 4 万本**（1 章）。膜を開けるしきい値の直前の縁で、三角形が距離関数より最大 0.2 薄い。
   なくすには、縁の厚みを格子の解像度で扱う（しきい値の前後で値を不連続にする・縁だけ細かい格子で作る）必要がある。
2. **照準を最大の上向き（1.0）にすると地表へ出られない**（変更前も同じ）。60° の坂は掘った穴の中でも登り切れない。
   z = 8.3 の既存の検査の道は出口の先が岩で、実時間のずれで結果がばらつく。
3. 掘った穴のそばではカメラの更新が約 0.7 ms 増える（先読みの分の光線）。FPS には出ていないが、CPU の遅い端末では未計測。
4. 小石（見た目だけ、当たり判定なし）がカメラの手前に入って、カニを隠すことがある（既存。`sheet-touch-independence.jpg` の変更後 3）。
5. トンネルの中で横（壁）を向くと、近い視点は後ろへ引けずカニが画面いっぱいになる（既存の `near` の作り。変更前と同じ）。
6. 移動と掘る向きを分けたので、掘る向きへ進むにはスティックもその向きへ倒す必要がある。カメラが斜めにあると「前」が
   掘る向きとずれ、トンネルの壁に寄る。
7. 視点をドラッグしている間は位置の動きを制限しないので、狭い所でドラッグするとカメラが跳ねることはある（変更前と同じ）。
8. iPhone の実機では確認していない（タッチは Chromium の CDP の模擬）。
