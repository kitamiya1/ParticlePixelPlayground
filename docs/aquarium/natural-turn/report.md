# 第 9 段階：自然な方向転換の比較試作（踏ん張り旋回）

その場で方向転換するとき「胴体だけが回転して脚が追従しているように見える」問題に対し、接地している脚が地面を押して体の向きを変える
旋回（C：踏ん張り旋回）を試作し、A 従来（歩行周期）・B 現行（接地 IK・接地主導）・D 旋回中だけ歩行周期 と同じ条件で比べた。
**見た目の採用判断は未定（ユーザーが比較動画で判断する）。既定は B のまま（main と同じ動き）で、設定の「旋回」で C・D を選べる。**

- 比較動画（同期再生・スロー・1 枚送り・場面ごとの数値）：Artifact「カニの方向転換 比較」
- このフォルダ：`turn-<n>.webp`（場面ごとの 2 × 2 比較動画、20 枚 / 秒）・`strip-<n>.jpg`（連続画像。行 = A〜D、列 = 0.15 秒ごと）・`scene-<n>.json`（動画と同じ実行の数値）
- 場面の番号：0 その場で 90°・1 その場で 180°・2 左右に連続して方向転換・3 歩きながらゆっくり曲がる・4 ダッシュしながら曲がる・5 岩の上で方向転換・6 斜面で方向転換

## 結論（測定から言えること）

- **C は B より脚が伸びきらない。** 描いた脚の最大伸び（付け根から足先 ÷ 届く長さ）は B 1.01〜1.32・C 0.97〜1.07。B はその場で回り始めに胴体だけが
  大きく回り（最大 490〜522°/秒）、置いたままの足先へ脚が伸びきってから踏み替える。C は回る向きへ先に足を置き、回る速さを抑える（343〜376°/秒）。
- **操作の軽快さは落ちていない。** 90% まで回る時間は 90° で 0.32 → 0.28 秒、180° で 0.58 → 0.53 秒、岩・斜面で 1.57 → 1.53 秒。平均の速さも同じ。
- **足先の滑りは B・C とも 0**（ダッシュだけ B に 1 フレーム 0.26 の動きがあり、C は 0.03）。A・D は回るたびに足先が地面を滑る（合計 2.5〜18.6）。
- **変わらなかった点**：踏み替えの回数は B とほぼ同じ（90° だけ C が多い 24 → 31）。旋回の内側 / 外側の歩幅の差は数値ではほとんど出ない
  （横歩きで曲がると曲がる中心が体の前後に来るため、前側の脚と後ろ側の脚の差になる。C でも前 0.415 / 後ろ 0.362、B は 0.430 / 0.375）。
  「行き先が近い脚は番を飛ばして踏ん張る」は 1 場面で 0〜1 回しか働かなかった。
- **D（旋回中は歩行周期）は採用候補にしない。** 切り替えの跳ね・接地の破綻は起きず、伸びも小さいが、回る間は足先が滑る（A と同じ）。
- **壁・天井・地形への回帰は無い**（B を 2 回測ったばらつきの範囲。下の「回帰」）。C の旋回は床だけで働く。

## 仕組み

`CrabFeet.ts`（PIVOT・turnStyle）・`CrabController.ts`（PIVOT_TURN・inp.pivot）・`CrabRig.ts`（turnStyle・TURN_CYCLE）・`AquaUiPrefs.ts`（旋回の設定）・`main.ts`

C 踏ん張り旋回（`turnStyle = 'pivot'`）：

1. **回る分の先読み**：踏み替えるとき、行き先 = 理想の位置 + 歩く分（B と同じ）+ 回る分。回る分は、理想の位置を体の中心（根）のまわりに
   「いまの回る速さ × （踏み替えの時間 + 接地の時間の半分）」（上限 1.0 rad）だけ回した所。接地の間、足先が理想の位置の前後に同じだけ振れる。
   B は回転を先読みしないので、置いた直後から足先が体の回転に置いていかれ、伸びきってから踏み替えていた（「胴体だけ回って脚が追従」の原因）。
2. **歩幅と周期**：足先の速さの目安 = 歩く速さと（回る速さ × 理想の位置の半径の平均）の合成。回っている間は歩幅を 0.3 まで伸ばす（回る速さ 0.8〜2.4 rad/秒で
   0 → 0.3）。速さで決まる短い歩幅のままだと細かく踏み替えてバタつく。
3. **回る速さ（コントローラ）**：横歩きの向きへ体を回す速さに上限（その場 6 rad/秒、歩く速さに応じて最大 11）。回る速さは目標へ 22 / 秒で近づける
   （回り始めの 1〜2 フレームで一気に回らない）。目標は従来と同じ（残りの角 × 7）。
4. **回り始めの前に上げた脚**：回る速さに合わせて残りの踏み替えを速くする（遅い踏み替えのまま体が回り、着地点が届かなくなっていた）。
5. **内側の脚**：番が来ても行き先が今の所から 0.34 × 歩幅より近い脚は、踏み替えずに接地したまま。
6. **床だけ**：張り付いている・面の移り（FaceHint）・縁（Ledge）の間は B と同じ。

D 旋回中は歩行周期（`turnStyle = 'cycle'`）：床で体の回る速さが 2.2 rad/秒を超えたら接地 IK の重みを 0 へ（従来の歩行周期の脚）。0.9 rad/秒未満が
0.12 秒続いたら、足場をいまの理想の位置へ置き直してから接地 IK を混ぜ戻す。

参考：実際のカニの旋回を直接測った研究は見つからなかった。横歩きでは進む側の脚が引き（関節の屈曲）・後ろ側の脚が押す（伸展）、4 本ずつ交互に踏み替える
（Blickhan & Full 1987 ghost crab、Chapple 2012 hermit crab）。C の「接地した脚で押して回り、回る向きへ先に足を置く」はこれに沿う。

## 回帰（`tools/turn_regress.js`：climb_lead_test の 9 場所・foot_ik_test の 9 場所を B → C → B の順で）

- 壁・天井（接地主導の壁登り・天井への移り）：張り付き・天井に着く時刻、接地の本数、体の回転、空中のフレーム、支えの喪失は、どの場所でも B の 1 回目と 2 回目の
  間に収まった（例：岩の柱の張り付き B 0.42 / C 0.77 / B 0.77 秒、天井を掘る B 落ちない / C 落ちる / B 落ちる）。最初の試作は壁の上でも C の脚が働いて
  ばらつきの外へ出たので、C は床だけにした。
- 地形（接地 IK）：滑り 0・面の上 1.00 は全場所で同じ。伸びの最大は 8 場所中 4 場所で C が小さく（洞窟の床・壁・天井 1.56 → 1.14 など）、3 場所で C が少し大きい（+0.02〜0.04）。
  接地の最小は C が同じか多い。
  足場を掘って消す：B 0.97 / C 0.99、宙に残る足先 0（震えの再発なし）。

## 食い違い・気づいた点

1. **入力が体の正面ちょうどのとき、回る向きが決まらない**（既存）：`CrabController` の横歩きの向きは「移動方向 ±90° のうち近い方」で、ちょうど 90° ずつ離れると
   浮動小数の誤差でどちらへ回るかが決まる。最初の撮影で A だけ逆へ回った。検証の入力は 0.2 rad ずらしてそろえた（ゲームの動きは変えていない）。
2. **B のダッシュで、接地した足先が 1 フレームに 0.26 動く**（既存。C では 0.03）。原因は調べていない（接地中の足先を面へ寄せる処理・置き直しの可能性）。
3. `foot_ik_test.js` の説明では planted を「接地（+ 踏み替え中）の脚の最小の本数」としているが、コードは踏み替え中を足した値 `n` を使わず
   `support.planted`（接地だけ）を記録している。
4. 第 8 段階の報告は「場所ごとに数値は ±数 % 揺れる」としているが、同じページで続けて測ると張り付きの時刻が 0.42 → 0.77 秒のように大きく変わる場所がある
   （前の場所で掘った・動かした状態が残る、順番の影響）。今回の回帰は B を前後 2 回測って幅を見た。
5. `CrabFeet` の GAIT の説明は「踏み替えの時間 = S / 速さ」だが、コードは × 0.92。
6. `CrabFeet.GAIT.turnR`（回る足先の半径 0.42）は B だけで使う。C は理想の位置の半径の平均をフレームごとに測る。

## 試し方

ブランチ `feat/crab-natural-turn` の開発ページ（`npm run dev` → `/aquarium.html`）で、設定の欄の「旋回」から 現行 / 踏ん張り旋回 / 旋回中は歩行周期 を選ぶ
（歩き方が「接地主導」「接地 IK」のとき）。既定は「現行」。

数値の取り直し：開発ページ `?nosave` で `climb_helpers.js`・`turn_test.js` を読み込み、`__tn.all(['A','B','C','D'])`。
撮影：`node tools/frame_recv.mjs <出力>` を起動してから Playwright で `tools/turn_shots.js`、`python tools/make_turn_media.py <出力> <動画の出力>`。
