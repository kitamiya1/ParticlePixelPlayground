押しているポインターの数。

### 1.2 原因として特定できなかった部分

- **iPhone で実際にどの指の動きが拡大を起こしたかは特定できていない**。Chromium の模擬では、セーブの欄の上のピンチでもページは
  拡大しなかった（Chromium と WebKit で、スクロールする要素と touch-action の扱いの細部が違う）。iOS で起こりうる経路として次を
  考えたが、どれが当たりかは実機の `?diag` で確かめる必要がある：
  1. セーブの欄を開いた状態で、その上から始めたピンチ（1.1 の 4）
  2. 画面の端（ホームバーの辺り・横画面のノッチの辺り）や、ツールバーが縮んだ直後に、どの要素にも当たらない所から始めた指
     （WebKit が touch-action の領域を描画の層ごとに持つため、要素の無い所はふつうの拡大になりうる）
  3. 回転の直後など、touch-action の領域が更新される前の一瞬に始めたピンチ
- **ダブルタップでの拡大**は、模擬では Canvas・左上の表示・説明・セーブの欄のどこでも起きなかった。iOS での有無は未確認。

アクセシビリティ：viewport に `user-scalable=no` / `maximum-scale` は付けない（「元に戻す」を押した一瞬だけ）。端末の「ズーム機能」
（画面全体の拡大鏡）と Safari の「ページの拡大／縮小（aA）」は止めない（どちらもページの倍率 `visualViewport.scale` とは別で、
操作もずれない）。止めるのは、ゲームの操作（2 本指 = カメラのズーム）と取り合いになるページのピンチだけ。

### 2.1 知らせの「保存して読み込み直す」と保存の説明（公開前の見直し）

最初の版（`da5dc40`）は `saver.flush()` の結果を見ずに `location.reload()` し、知らせには状態に関係なく「進捗は自動で保存されています」と
出していた（保存に失敗していても、別のタブと競合して保存していなくても、`?nosave` でも）。次のように直した（`AquaViewport.ts`、`main.ts`）。

| 保存の状態 | 知らせの説明 | 「読み込み直す」のボタン |
|---|---|---|
| 保存済み | 保存済み（最後の保存の時刻） | 保存して読み込み直す：保存できたら読み込み直す |
| 未保存の変化あり（保存中を含む） | まだ保存していない変化がある（最後の保存の時刻 / このタブではまだ保存していない） | 同上 |
| 保存できていない | 保存できていない（理由）。読み込み直すと最後の保存より後の進捗が消えるおそれ。先に書き出しを | もう一度保存を試し、できたときだけ読み込み直す。できなければ読み込み直さず、ボタンが「保存せずに読み込み直す」（赤）に変わり、もう一度押したときだけ読み込み直す |
| 別のタブと競合 | このタブからは保存していない。読み込み直すと別のタブの進捗に替わり、このタブの進捗は消える。先に書き出しを | 「読み込み直す…」→ 押すと「このタブの進捗を捨てて読み込み直す」（赤）→ もう一度押すと読み込み直す |
| 保存しない（`?nosave` / 保存先が使えない） | このタブは保存していない（どちらの理由かも出す） | 「読み込み直す…」→「保存せずに読み込み直す」（赤）→ もう一度で読み込み直す |

- 保存が 8 秒たっても終わらない（iOS の IndexedDB が応答しない例を想定）ときも、保存できなかったとして読み込み直さない。
- 「進捗を書き出す（ファイル）」を知らせに追加（セーブの欄の「書き出す」と同じ。競合中は「-このタブ」の名前で、保存はせずファイルだけ）。
- 説明は知らせを出している間 0.5 秒ごとに実際の状態（`AutoSaver.state`・未保存の秒数・`SaveStore` の最後の失敗の理由）に合わせる。
  `AutoSaver` は変化から 6 秒たつまで「保存済み」のままなので、知らせでは変化があれば「未保存の変化あり」と出す。
- 検証：`zoom_save_test.js`（6 つの状態。画像 `after_savefix_*.jpg`）

| # | 場面 | 結果 |
|---|---|---|
| 1 | 保存済み | 「保存済み（最後の保存 …）」→ 押すと読み込み直した |
| 2 | 未保存の変化（カニを動かした直後） | 「まだ保存していない変化があります」→ 押すと保存してから読み込み直し、カニの位置が残っていた |
| 3 | 保存先の書き込みを失敗させた | 1 回目は読み込み直さず「保存できていません（理由）」・ボタンが赤。書き出したファイルは `ppp-aquarium-save` の形式。2 回目で読み込み直し、閉じる直前の控えから進捗が戻った（`fromJournal`） |
| 4 | 書き込みが返らない | 8 秒で「保存が終わらないため、読み込み直していません」 |
| 5 | 別のタブが保存して競合 | 1 回目は読み込み直さない。「-このタブ」のファイルを書き出せた。2 回目で読み込み直した |
| 6 | `?nosave` | 「?nosave で開いています」。1 回目は読み込み直さず、2 回目で読み込み直した |

**ブラウザの制約**：iOS Safari は viewport の設定でピンチの拡大を禁止できず、ページの倍率をスクリプトで直接戻す API も無い。
「元に戻す」の仕掛け（maximum-scale を一瞬だけ付ける）が iOS で効くかは未確認。効かない場合の手段は、知らせの上でつまんで縮める
・保存して読み込み直す（Safari が読み込み直しで倍率を戻すかも実機で確かめる）。

## 6. iPhone の実機で確かめること

### 6.0 プレビュー（公開中のゲームとは別）

`docs/aquarium/tools/ios_preview.ps1` が、PR のブランチを一時フォルダの worktree でビルドし、この PC の `vite preview` を
Cloudflare の Quick Tunnel（アカウント不要）で `https://<ランダム>.trycloudflare.com` に出す。

- 公開中のゲーム（`https://kitamiya1.github.io/ParticlePixelPlayground/`）とは**オリジンが違う**ので、IndexedDB・localStorage
  （セーブ・説明を閉じた記録）は共有しない。GitHub Pages・`pages.yml`・main には何もしない（このブランチへの push では Pages は動かない）。
- PC が起きていて、スクリプトが動いている間だけ見られる。起動し直すと URL は変わる。
- 確かめたこと（Chromium のスマホの模擬・iPhone の UA）：`?diag&nosave` で診断の表示が出る（倍率・visual・inner・canvas…）、
  保存先は memory・状態は「保存しない」、IndexedDB のデータベースも localStorage の鍵も作られない。2.2 倍に拡大すると診断の倍率が
  2.200・知らせに「?nosave で開いています」。画像 `preview_diag_nosave.jpg` / `preview_diag_nosave_zoomed.jpg`。

### 6.1 手順（短縮版）

## 7. 文書とコードの食い違い（気づいたもの）

- `aquarium.css` の修正前の注釈は「html / body の `touch-action: none` で、HUD や説明の上から始めた指でページが拡大されない」と
  していたが、中でスクロールする欄（セーブの欄）では先祖の `none` が効かず、しかも `manipulation` はピンチの拡大を許す値だった
  （1.1 の 4）。今回、セーブの欄を `pan-y` にし、注釈も直した。
- 依頼の文面の「12 秒後に自動で消える」は、コードでは `opacity: 0` にするだけで、要素は残っていた（`#help.fade`。`pointer-events: none`
  なので操作の妨げにはなっていなかった）。今回、説明の欄は閉じると `display: none` になる。
- `compare_regression.js` は基準と修正後の 2 つのホストを前提にしている（1 つだけ渡すと止まる）。最初の版では同じホストを 2 回渡して
  描画できることだけを確かめていた（main との比較にはなっていなかった）。公開前の見直しで、main と PR のビルドを別々に作って比べ直した（5 章）。
- 最初の版の報告（2 章）・知らせの文は「保存（`AutoSaver.flush`）してから読み込み直す」「進捗は自動で保存されています」としていたが、
  コードは `flush()` の結果（失敗・競合で false）を捨てて必ず読み込み直し、文は保存の状態に関係なく出ていた。2.1 で直した。
- `compare_regression.js` の先頭の注釈は「設定は compare_config.json」だが、`globalThis.__over` でも上書きできる（コードでは
  `Object.assign(設定, __over)`）。今回は compare_config.json を一時的に書き換えて使い、元に戻した。

## 8. 残る問題

- 拡大の原因の経路は実機で特定できていない（1.2）。対策は「起こりうる経路をまとめて塞ぐ + 起きたら気づいて戻す」で、iOS での効果は未確認。
- 「元に戻す」（viewport の設定を一瞬変える）が iOS Safari で効くかは未確認。
- Chromium の模擬では、知らせの上の 2 本指でページの倍率を戻す操作を確かめられなかった（倍率の上書き `Emulation.setPageScaleFactor`
  の間はつまんでも変わらない）。
- 横画面で詳しい説明を開くと、スティックの上に重なる（読んでいる間は操作できない。閉じれば戻る）。
- 短い案内・詳しい説明は左上の表示（HUD）に重なる（「×」で閉じるまで）。
