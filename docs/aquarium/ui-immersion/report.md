# 第 1 段階：操作ボタンの改善と没入感のための表示の整理

画面の文字や輪で説明するのをやめ、カニや物の動き・音・物理の反応で伝える方向への最初の段階。
画像は `before-*`（公開中の main `a0e8358`）と `after-*`（この PR）を同じ手順（`tools/ui_immersion_shots.js`）で撮った。

## 実装

### スマホの操作ボタン（`src/ui/TouchControls.ts`・`aquarium.css` の末尾）
- 文字の代わりに簡単な線画の印：↑ ジャンプ、» ダッシュ、地面と ↓ 掘る（盛るのときは山と ↓）、ハサミ 挟む（開いた / 閉じた印）、
  カメラ 切り替え、小さな横長 = 掘る ↔ 盛る（いま使う方が明るい。下の細い帯は手持ちの砂）。読み上げ用に `aria-label` を付ける。
- 見た目の円（`.face`）と指の当たる範囲（ボタン自体・透明）を分けた。見た目は以前の **75%**（25% 小さく）、
  当たる範囲は円より 12px × 大きさ ずつ外側（既定で 9px）。
- 背景の濃さは **25%**（以前は 70〜80%）。押している間・挟むスイッチが閉じている間も 45%（上限 50%）までしか濃くしない。
  印は白い線に影を付け、明るい砂の上でも読める。
- 位置は「右下の角から円の中心まで」を大きさに合わせて縮める（小さくすると隅へ寄る）。ただし 72% 未満にはしない
  （小さくしてもボタンの間が詰まりすぎず、指の当たる範囲がとなりの円に掛からない）。
- 縦長の狭い画面でスティックと重なる幅になったときだけ、挟むボタンを掘るボタンの上へ移す（`.narrow`。以前は幅 460px 以下で
  常に上へ移していた。75% なら 390px の縦画面でもスティックの右に収まる）。
- 大きさ（55〜110%）と濃さ（8〜60%）は右上の「🔊」→「音と設定」の欄で変えられる（localStorage `ppp-aquarium:ui`。保存データとは別）。

### 没入感（通常のプレイから外した表示）
| 表示 | 以前 | この PR |
| --- | --- | --- |
| 挟める物の輪（明るい輪・点線の輪）と「挟める」 | 常に | 出さない |
| PC の「E 挟む：小石」 | 常に | 出さない |
| 挟むボタンの縁が明るくなる（届く物がある） | 常に | 出さない |
| 左上の「挟む：巻貝（重い！）」「掘れる：砂」「盛れない：…」 | 常に | 出さない（詳細の欄の「照準」「ハサミ」に移した） |
| 巣穴の案内「穴の中で何かが動いている…」「挟む：見えている触角」 | 常に | 出さない |
| 引っ張っている間の輪・矢印・言葉（「引きすぎ！」「もう少し！」） | 常に | 出さない（砂粒・泡・カニの踏ん張りの砂・カメラの揺れ・音・振動は従来どおり） |
| 抜けた瞬間の「スポン！」の文字 | 常に | 出さない（衝撃の輪・砂煙・泡の柱・一瞬の間・転ぶ動き・音は従来どおり） |
| 天井歩きの「スティック↑」の矢印 | 常に | 出さない |
| 「重くて動かない」「滑り落ちた」「触角を挟んだ！」「盛る：…」の知らせ | 常に | 出さない |
| 仲間になったときの呼び方の説明 | 常に | 名前と一言だけ |
| 保存の失敗・別のタブと競合・ページの拡大・コントローラーの接続 | 常に | **常に（変えない）** |

- 外した表示は、「音と設定」の「案内を出す」で全部戻る（`body.aqua-guides`）。`?diag` で開いたときも出す（覚えない）。
  比較や操作に慣れないうちの補助・自動検証のため。
- 操作の説明は右上の「？」の説明に、ボタンの印の意味と「案内を出す」の場所を足した。

## 確認（Chromium のスマホ相当 390×844 縦・844×390 横、CDP のタッチ。PC 1280×800）

| 項目 | 前 | 後 |
| --- | --- | --- |
| ボタンの見た目の直径（ジャンプ / ダッシュ / 掘る / 挟む / スティック） | 96 / 72 / 80 / 80 / 128 | 72 / 54 / 60 / 59 / 96 |
| 指の当たる範囲（同） | 見た目と同じ | 90 / 72 / 78 / 77 / 119 |
| 背景の不透明度（ふだん / 挟むが閉じている） | 0.72〜0.82 / 0.94 | 0.25 / 0.45 |
| 画面に占めるボタンの面積（縦画面） | 15.1% | 8.4%（55% にすると 4.6%） |
| 見た目の円どうしの重なり・当たる範囲がとなりの円に掛かる | なし | なし（55%・75%・濃さ 50% の縦横）。110% の縦画面だけ、スティックとダッシュの当たる範囲が円の縁に少し掛かる |
| カニ（体と周り 4 点）がボタンに隠れる点 | 0 / 5 | 0 / 5 |
| 挟むボタンの円の外（当たる範囲の縁から 4px）をたたく | — | 閉じる → 小石を挟む |
| 小石の前の輪・「挟める」・「E 挟む：小石」・左上の「挟む：小石」 | 出る | 出ない |

- 回帰：`claw_touch_test.js` 8/8（文字の代わりに `aria-label` を読むよう直した）、`touch_test.js` 14 場面すべて OK、`help_test.js` OK 18 / NG 0、
  `pad_audio_test.js`（模擬のゲームパッド・左右のハサミ・引っこ抜き・音・スポン）すべて ok。
- 保存・復元：`tools/save_roundtrip_quick.js`（掘る → 保存 → 読み込み直し）で位置・穴・砂・カメラ・表示の設定が戻る。
- 性能：`tools/perf_quick.js`（公開版と開発版を交互に 2 回。同じ機械）で、更新 + 描画の命令 1.4〜1.8 ms / フレーム、実際のフレーム間隔は
  どちらも 15〜16 ms（画面の更新に合わせて頭打ち）。DOM の表示だけの変更で、差は測定の揺れの範囲。
- 本番ビルド：成功（既存の大きな塊の警告のみ）。

## 未確認・残る問題
- **iPhone 実機・実際のゲームパッドでは未確認**（Chromium のスマホ相当と模擬のパッドだけ）。印の読みやすさ・25% の濃さで景色に埋もれないか・
  当たる範囲の広さは実機で確かめたい。
- 110% の縦画面（390px）ではスティックとダッシュの指の当たる範囲が互いの円の縁に少し掛かる（見た目は重ならない）。
- 案内を外したことで、初めての人が「挟める物」に気づきにくくなる。触れたときの物の揺れ・音で補う方法を第 5 段階で検討する。
- 以前の撮影・検証の道具のうち、輪や手応えの表示を調べるもの（`grab_shots.js`・`tug_shots.js`・`buddy_helpers.js` の一部）は、
  `?diag` で開くか設定の「案内を出す」を入れて使う。
- 天井歩きの「スティック↑」の矢印を外した分は、第 2 段階のカメラ（天井でもカニと進む向きが分かる）と第 4 段階の歩き方で補う。
