## 1. ハイブリッド歩行

### 作り

- **見た目と移動の分離**：`CrabRig.gait = 'hybrid'`（既定）。`CrabFeet` は見た目に関係なく毎フレーム足場を探し、支え（`support`）を
  `CrabController` へ返す（main.ts は `rig.ikW` = 接地しているか、で渡す。見た目の重み `footW` では止めない）。
  縁の手がかり（`ledge` / `faceHint`）も接地主導と同じく渡すので、第 7・8 段階の崖降り・壁登り・天井移行はそのまま動く。
- **混ぜ具合 `footW`（0 = A、1 = B）**：`CrabRig.updateHybrid` が決める。
  - B を使う場面（1）：崖・段差の縁の近く（縁を見つけて 0.35 以内・待っている・脚で下ろしている）、壁 / 天井に張り付いている、
    逆さから起き上がり中、面の移り（xfer）・次の面を探している、縁を回り込んでいる。
  - それ以外は足場の複雑さ `CrabFeet.rough`：接地している足先の体の面からの高さのずれ（3.5〜8.5 cm）・足先どうしの高さの差（6〜13 cm）・
    足場の面の向きの差（1 − 内積 0.1〜0.25）・宙で構えている脚・足場が消えてから 1 秒。
  - ヒステリシス：0.55 以上で B へ、0.3 以下が 0.7 秒続いたら A へ。寄せる速さは B へ 4 / 秒（約 0.25 秒）、A へ 1.6 / 秒（約 0.6 秒）。
- **切り替えで足が飛ばない工夫**
  - B の踏み替えの番を A の歩行の位相（`stridePhase`）に合わせる（`GaitSync`）。同じ組の脚が同じ時に上がるので、混ぜている途中で
    片方だけ上がる脚が出ない。
  - A の足運びの間も、足先の高さだけ接地している足場の高さへ合わせる（±6 cm。前後左右の振りは A のまま）。平地の足先の浮き 7.7 % → 0.3 %。
  - 胴体の高さ・傾きの補正（B の `bodyOffset`）も `footW` で混ぜる（急に傾かない）。
  - B の「速さに掛ける割合」（接地の脚の数で 1 ↔ 0.6 と毎フレーム跳んでいた）をなめらかにした（下げは速く・戻しはゆっくり）。
- 設定：「歩き方」に ハイブリッド / 接地主導 / 従来。以前の既定（接地主導）を覚えていた人はハイブリッドとして読む（`gaitV`）。
  接地 IK（'ik'）は設定の欄から外した（コードと保存値では受け付ける）。

## 2. 崖を降りられず落ちる問題

### 再現（`tools/cliff_sweep_test.js`）

5 つの縁（低い岩・高い崖・斜めの岩・流木・高台）へ、縁に垂直な向きから 0〜135° 回した向きで 4 秒押し続ける。
変更前（main の接地主導）：25 条件中 5 回落ちた（高い崖 35°・60°・80°、流木 60°・100°）。

### 原因

1. **斜めに近づくと高い崖を段差と取り違える**：縁の下の高さを、押している向きの先の 3 点（0・0.3・0.6）だけで測っていた。斜めだと 3 点が縁に
   沿って並び、崖の途中の段・斜面を拾って「0.56 の段差」と判定 → 段差として胴体を縁の先へ下ろし始め、その先の 2 m の崖の上で
   脚 1〜2 本になり 0.25 秒で支えを失って落ちた（落ちたときの記録：段差・はみ出し 0.93・下の隙間 1.75・下の脚 1・接地 1）。
2. **降り切った判定が急な斜面で成立しない**：「足元の隙間 < 0.06」は、急な斜面では球の下の点と真下の地面が 0.1 ほど離れるので成立せず、
   縁の状態が解除されないまま次の本当の崖へ進み、古い縁を基準に判断していた。
3. **支えの判定が短すぎる**：脚が縁の下を探して宙で構える・踏み替える間に接地が一瞬 1〜2 本になり、0.25 秒で落ちていた（流木の丸い縁）。
4. **押し続けると踏み出す仕様**：足場が無いと 0.6 秒（段差・崖で脚が掛からないと 1.4 秒）で踏み出していた。
5. 縁を探すのは押している向きの前方だけ（縁に沿って漂って越えると従来どおり落ちる）。

### 直したこと

- 下の足場までの高さは、前方と、縁に垂直な向き（`dropOut`）の深い方で決める。段差として下ろし始めた先が段差より深ければ、
  いまの所で縁を探し直して崖・足場なしに分け直す（`ledgeStats.reclass`）。
- 降り切った判定の隙間を 0.06 → 0.16。
- 支えの待ち 0.25 → 0.6 秒（踏み替え中の脚も数える）。それでも足りなければ、縁の上の地形が残っていて胴体のはみ出しが 0.25 以下なら、
  落とさずに縁の上へ戻す（`keeps`）。縁の上の地形が消えた（掘った・崩れた）ときだけ落ちる。
- 脚で下ろしている間、胴体の下の隙間が 0.4 より大きければ縁の外へ進めない（脚が届かない高さで胴体だけが先へ出ない）。
- 押し続けても踏み出さない（`waits` を数えるだけ）。離れるのはジャンプ。
- 縁の無い向きへ漂って足場の無い所へ出かけたら、縁の外向きの成分を除いて縁の上で止める（`edgeGuard`。前の位置の下に足場がある
  ときだけ。前の位置の下も空いている＝崩れたなら落ちる）。
- 脚は縁の下の真正面に届かなければ、縁に沿って左右 ±0.11・±0.2 へずらして探す（凸角・斜めの縁）。

## 3. 砂を一度に多く盛る

- 砂山の寸法：1 回目の半径 0.2 → 0.22（たたくと小さく盛れる）、続けると 1 回 0.05 → 0.08 ずつ大きく、上限 0.42 → 0.56。
  押し続けて大きくなるほど、盛る向きに垂直な横へ伸ばしたカプセルになる（半分の長さ 0〜0.34）＝幅のある足場。
- 押し続けている間に新しく始める砂山は 0.34 から（小さな砂山から始めるのは押した最初の 1 回だけ）。
- 置く所：カニに近すぎて大きくできない所・もう砂の中の所は飛ばし、照準の先（最大 1.0 先）へずらして真下の面へ下ろす（穴は底から埋まる）。
  積むときは、上の端がカニの足元 + 0.3 を越えるなら先に奥・左右の肩へ広げる（目の前に壁を作って進めなくならない）。
- 保護：カニ・仲間・挟める物との空け幅 0.1 → 0.2（砂山どうしのなじませと地面とのなじませが重なると 0.1 ふくらみ、押し続けるとカニが
  0.1 めり込んで動けなくなった）。ガラス・管・発見物・底の打ち切りは従来どおり（砂山の両端も確かめる）。
- 描画と当たり判定の一致：既存の光線検査（`sand_test.js` の seam / meshMound / meshTunnel）で食い違い 0。

| 試験（`tools/sand_fill_test.js`） | 変更前 | 変更後 |
| --- | --- | --- |
| 平らな砂で照準を固定して 5 秒押し続ける | 0.36（0.07 / 秒）・高さ 0.92・幅 0.9 | **1.62**（0.32 / 秒）・高さ 1.21・幅 1.5 |
| 照準を左右に振って 10 秒 | 0.70・幅 1.4 | **4.26**・幅 2.5 |
| 穴（体積 15.0）を縁から 45 秒埋める：照準固定 | 1.6 % | 15.6 % |
| 同：照準を振る | 0.8 % | 25.2 % |
| 同：届かなくなったら少し前へ進む | 14.9 %（砂 4 を使い切る） | 25.3 % |
| 同：1 回ずつたたく（30 秒・151 回） | 2.3 % | 29.7 % |
| 盛った体積あたりの編集の数（地形データ量） | 約 20 個 / 体積 1 | 約 9 個 / 体積 1 |

穴を一か所に立ったまま埋めると、届く範囲が埋まった所で「カニに近すぎる」で止まる（前へ進めば続けられる）。

## 4. 砂の上限と消失

- `SAND.capacity`（4）を撤廃。掘った砂はすべて手持ちになる（試験：15.0 掘って 15.0 持つ。変更前は 4 を持ち 11.0 を捨てた）。
- 盛る量の判定と消費の整合：盛る前に「増える体積の見積もり × 0.6」が手持ちを越えない大きさにし、盛った後は測った体積だけ減らす
  （変更前は手持ちを越えて盛れた分を減らさず、砂が増えていた）。測る範囲の余白を 0.15 → 0.25（なじませの分の測り漏れ）。
- 帳尻：掘る → 盛る → 掘り直す の各段階で、手持ちと地形から数えた「掘った − 盛った」が ±0.001 で一致。盛った砂を掘り直すと砂が戻る。
- 救済：読み込んだ直後と、手持ちが無いのに盛ろうとしたときに、地形から「手元にあるはずの量」を数え直し（フレームに分けて 1 フレーム 1.2 ms まで）、
  手持ちが少なければ差を戻して知らせる（「砂を N 杯ぶん手持ちに戻しました」）。多いときは減らさない。
- 古いセーブ（`tools/sand_rescue_save.js`）：main の版で 15.0 掘って 11.0 捨てた保存を、新しい版で読む → 読み込めた・編集 29 個・地形の指紋が一致・
  手持ち 3.88 → 32 フレームで 14.88（地形から数えた量と一致）・歩き方の設定（以前の既定 lead）はハイブリッドとして読む。
- 保存の形は変えていない（版 2 のまま）。手持ちの検証の上限は `SAND.maxStore`（100000）。
- 表示：手持ちは杯数だけ（「n/80 満杯」をやめた）。帯は持っている量の目安（2 で約 63 %、6 で約 95 %）。新しい UI は足していない。
- 長時間：盛る 1 回の編集の数は減った（上表）。編集の上限 `DIG.maxPrims`（6000）は従来どおり。

## 6. 残る問題

1. 丸い流木の側面を斜め（50°）に横切ると、小さく跳ねながら側面を滑り降りることがある（崖スイープ 40 条件中 1）。
