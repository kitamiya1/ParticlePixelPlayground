# 方式 F：Hybrid (E+C) 画質改善（v2）

計測日：2026-11-21　ブランチ：`feat/hybrid-quality`（`feat/pixel-mesh` の `db7b93d` から分岐）
前段：`ecf-report.md`（F v1 の試作と E / C / F の比較）

この資料では、**計測で確かめた事実**には「計測」、**画像を見ての評価**には「見た目」と付けて分けています。

## 1. 変更の概要

| 項目 | v1（改善前） | v2（改善版） | 設定 |
| --- | --- | --- | --- |
| 道・地面 | 地形の網（格子 0.25）の頂点に、近くの粒の色を写して補間 | 地面を**画素ごとに塗る**専用マテリアル。道の距離場（CPU で焼いたテクスチャ）の内側にボロノイの石・目地・土・苔を描き、石の縁の法線を傾けて光の段階化で凹凸を出す。道のふちは揺らぎのある土の帯。草地は細かな 3 段の明暗 | `hybridRoad`（5 種のプリセット）、`hybridGroundDetail` |
| 草 | C 側の円盤 1 層（花・つた・木の葉と混在）。密度は C の「粒の密度」で全体を間引く | 草の葉だけを別の層にし、**葉 1 枚単位**で間引く（花・つた・葉は減らさない）。根元の色を地面の色へ寄せる、遠景で順位の後ろの葉を描かない | `hybridGrass`, `hybridGrassBlend`, `hybridGrassSize`, `hybridGrassFar` |
| キャラ周辺 | 足元の草がそのまま | 足元の草を外側・下へ押し倒す、足元の接地影（地面）、キャラの明るさの持ち上げ + 輪郭側の縁の光 | `hybridTrample`, `hybridContact`, `hybridCharLift` |

- **改善前の復元**：プリセット「ハイブリッド：改善前（v1）」（値は `settings.ts` の `HYBRID_V1`）。この値で撮った 12 視点は、ブランチ作成直後のコードの F と**画素単位で一致**した（計測：差のある画素 0。最初の 4 枚だけ左上の操作説明の帯が写り込んでいたのは撮影側の問題で、後述）。
- **A〜E への影響なし**：A / B / C / D / E を標準視点・キャラ歩行の 2 視点で、変更前のコード（`git stash`）と変更後で撮り比べ、10 枚すべて差のある画素 0（計測）。
- 草の葉の順位は粒の生成時に CPU 側データ（`ParticleBuilder.grassRank`、シェーダーには渡さない）として持たせた。乱数列は消費しない（根元の位置のハッシュ）ので、粒データそのものは変わらない。

## 4. 見た目の評価

### 道（最優先）

- 見た目：v1 のピンク・水色・白の大きなまだらが消え、**石・目地・土のふち**が描き分けられた。石は 1 個ずつ輪郭が読め、日なた側の縁が明るく・反対側が暗くなるので石畳の凹凸が出る。
- 見た目：配色はまとまり（灰色の石 + 暗い目地 + 茶色のふち）を保ちつつ、石ごとの明るさの揺れと、パレットで黄土色に寄る石が混ざるので単調な一色の面にはならない。
- 見た目：遠距離（ズーム 33）・浅い角度でも道は一色にならず、石の模様か大きめの明暗の揺らぎが残る（石が 1〜2 画素より小さくなると平均色 + 揺らぎに切り替え）。
- 見た目：道の縁は v1 では網の頂点の補間でぼけていたが、v2 では画素単位の境界 + 揺らぎのある土の帯になり、草地との境目がはっきりした。
- 推奨：`cobble`（石畳：灰）。草の緑・キャラの青と色相がぶつからず、遠景でも道として読める。`sandstone` は明るく楽しい雰囲気、`dirt` は素朴な小道に向く。`slate` は日なたの石が水色に寄りやすく、推奨しない。

### 草の密度（60 / 70 / 80 / 100%）

- 見た目：標準視点では 4 段階の差は小さい。近距離・浅い角度で、密度を下げるほど地面の起伏（明暗の段）が読みやすくなる。
- 見た目：60% では草むらの「密集感」が薄れ、草地が少し平らに見える。80% はほぼ 100% と同じ。
- 見た目：花畑はどの密度でも花が埋もれない（花は間引かない）。70% 以下で花の周りの草が減り、花の色が少し目立つ。
- 計測：重ね塗り・GPU 時間・ちらつきの差は小さい（上表）。
- 推奨：**70%**（密集感を保ちつつ、地面の形が 100% より読める）。

### E の地面と C の草のなじみ

- 見た目：草の根元を地面の色へ寄せ（45%）、草地の地面に細かな 3 段の明暗を足したことで、「つるっとした面の上に粒が乗る」感じは和らいだ。草の多い所の地面をわずかに暗くしたので、草むらの影のように見える。
- 見た目：道と草地の境界は土の帯で区切られ、v1 の「道の色が草地へにじむ」状態は無くなった。
- 見た目：岩の周辺・木の根元の変化は小さい（岩・幹の根元の地面は草地の処理だけ）。岩の根元の接地感（暗い縁や土）は今回入れていない。

### キャラクター周辺

- 見た目：足元の草を押し倒すので、足首が草に隠れにくくなった。草地では足元の濃い影の円がはっきり残る。
- 見た目：縁の光（`hybridCharLift` 0.2）で、灰色の石畳の上でも脚の輪郭が石から分かれて見える。v1 は暗い脚が暗い石・目地と同化していた（v1 の道は明るいまだらだったので、むしろ目立っていた）。
- 見た目：歩行・走行の姿勢でも、押し倒しは足の位置ではなくキャラの中心で決まるので、踏み出した足の先の草は残る（大きな破綻ではない）。
- 見た目：草・花とキャラの前後関係は v1 と同じ（同じ深度バッファ）。押し倒した草がキャラの体に重なる箇所は見当たらなかった。

## 5. 問題点・未検証

- **パレットの灰色が足りない**（見た目）：既定パレット（草原 38 色）は灰色が 4 段しかなく、日なたの明るい灰色が黄土色・水色に寄る。`cobble` は石の色を少し青みのある中間の灰色にして目立ちにくくしたが、道の向き違い（`f2/after/road-yaw.png`）では日なたの石が水色に寄る。パレットに明るい中間の灰色を 1〜2 色足すと解消できるが、A〜E の見た目も変わるので今回は変えていない。
- **遠景のちらつき**（計測）：v2 は v1 より +0.1 pt。
- **生成時間**（計測）：C 側の用意が +40〜50 ms（葉の順位の並べ替え）。初回の切り替えは 0.84〜0.92 s のまま（大半は v1 と同じ E 側のメッシュ）。
- **岩の根元**（見た目）：岩と草地の境界は v1 からほぼ変わらない。
- **左右比較で v1 と v2 を並べられない**：左右比較は方式を左右に選ぶ仕組みで、両側が同じ設定を共有するため、「F v1 ｜ F v2」を同時には描けない。比較は v1 プリセットと撮影画像で行う。
- **ベンチマークの「描いた数」**：遠景の間引きでつぶした草の円盤も数に含む（頂点シェーダーで三角形をつぶすため、CPU 側の数は変わらない）。
- **未検証**：スマホ実機の GPU 時間・発熱（デスクトップのブラウザで 390×844 にして表示・パネル操作を確認しただけ）、スマホ実機のタッチ操作（タッチ操作のコードは変更していない）、他の GPU（計測は RTX 2060 SUPER のみ。この GPU では F の条件どうしの差がぶれに埋もれた）、風ありでの押し倒しと風の揺れの重なり（撮影・計測は風 0）、カメラの手動操作での歩行・走行の連続した見え方（静止画のみ）。

## 6. 推奨設定（v2 の既定値）

| 設定 | 推奨（既定） | v1 | 理由 |
| --- | --- | --- | --- |
| 道・地面の配色 | `cobble` | `legacy` | 道の読みやすさが最も改善し、草・キャラと色がぶつからない |
| 草の密度 | 70% | 100% | 密集感を保ちつつ地面の形が読める。コストの差はこの GPU では誤差 |
| 草の根元を地面の色へ | 45% | 0% | 地面と草の質感の差を和らげる。上げすぎると草が地面に溶けて平らになる |
| 草の円盤の大きさ | ×1.00 | ×1.00 | 大きくすると密度を下げた分を補えるが、遠景の粒が太る |
| 遠景で残す草 | 50% | 100% | 遠景の重ね塗りを減らす（断片/画素 −15%） |
| 草地の地面の細かな明暗 | 50% | 0% | 草の粒と地面の質感をそろえる |
| 足元の草を押し倒す | 80% | 0% | 足元を見せる |
| 足元の接地影 | 50% | 0% | 道の上でも接地感を出す |
| キャラクターの明るさ・縁の光 | +20% | +0% | 石畳の上で脚の輪郭を分ける |

## 7. 撮影・計測の手順

1. 開発サーバー（`npm run dev`）を開き、Playwright でビューポート 1280×800（キャンバス 950×800）にする。localStorage は空（起動直後の設定 = 既定値）。
2. `tools/shots_f.js` を実行（視点の一覧と `window.__mk` を用意）。
3. `window.__jobs = [{ dir, shots: __mk(prefix, 設定の上書き, 視点?) }, …]` を入れて `tools/capture_f.js` を実行。
4. `python docs/compare/tools/make_sheets_f2.py` でシートを作る。
5. 性能は `window.__perfConfigs` / `window.__perfViews` を入れて `tools/perf_f.js`（内部で `window.__ppp.runTool(種類, 方式)` を使い、既存の比較ツールを F だけに絞って実行する）。

追加したデバッグ用の入口（`main.ts`）：`window.__ppp.freeze`（ゲームの更新を止めて dt = 0 で描く）、`window.__ppp.runTool(kind, methods)`（比較ツールを方式を絞って起動）。

## 8. 既存コード・資料との食い違い（記録）

- **`tools/capture.js` の「時刻を固定（dt = 0）」は実際には効いていなかった**：撮影中もゲームの更新が動くため、①キャラの状態が速度 0 から毎フレーム idle に戻り、`state: 'walk' / 'run'` を指定しても待機の姿勢で写る、②`cam.dx / dz` で注視点をずらしてもカメラの追従で 30 フレームの間にキャラへ寄っていく。`ecf/` や `abcde/` の「キャラクター」「ずらした視点」の画像はこの影響を受けている可能性がある。今回は `capture_f.js` で `freeze` を使って止めた。
- **前回レポートの「操作説明の帯の差」の原因**：Headless Chromium がタッチ端末と判定され、操作説明が起動後 9 秒で消える。撮影開始が 9 秒より前だと最初の数枚にだけ写る。`capture_f.js` では非表示にした。
- **道のまだら模様の原因**：`ecf-report.md` は「近くの粒（花びら・石）から写しているため」としていたが、主因は①石畳の模様（ボロノイのセル約 0.45 単位）を地形の網（格子 0.25 単位）の頂点でしか拾えず、石と目地が大きな色の塊になること、②明るい暖色の灰色の石が、灰色の少ない既定パレットでピンク・水色・白に寄ることだった（粒データの石の色は灰色〜ベージュで、ピンクや水色は含まない）。
- **`hybridCounts().surfelTotal`**（比較ツール）は C 側の円盤の総数を `surfel.worldTotal` だけで数えていた。草を別の層にしたので、草の層も足すように直した。
- **`ecf-report.md` の「草の密度は C の設定が効く」**：v2 でも C の「粒の密度」は F 全体（花・葉・草）に効き、`hybridGrass` はさらに草の層だけに掛かる。
