動的比較・計測はアプリ内の既存ツール（ちらつき計測・性能ベンチマーク・隙間・重ね塗り解析）を 4 方式に対応させたものをそのまま実行し、JSON（`abcd-results.json`）を保存した。

## 方式 D の実装の要点

- **占有グリッド**：地形 = 高さ場の柱（島の底〜地表）、樹木・岩 = 既存 SDF（`sdfObjects` の樹冠・幹・岩）の内外判定（d ≤ 0）、キャラクター = 部位 SDF のなめらかな和集合。草花・雲は立体の定義がないので粒の位置を埋める（雲は粒の半径ぶんの球）。
- **描画**：空気に面した面だけを取り出し、面 1 枚 = 四角形インスタンス 1 個（`InstancedBufferGeometry`）。立方体ごとの Three.js オブジェクトは作らない。面を向き（±X・±Y・±Z）ごとに 6 組に分け、カメラから見て裏向きの組は丸ごと描かない（平行投影では常に 3 組）。
- **色・日照・風**：A・B・C と共通の点群から、ボクセルの近くの点の値を写す。光・影・霞は A・C と同じ GLSL、後処理（輪郭・ディザ・減色）も A・C と同じ PixelPipeline。
- **キャラクター**：静止姿勢で 1 回だけボクセル化し、各ボクセルを最も近い部位のボーンに割り当てて剛体として動かす（毎フレームのボクセル化はしない）。面の省略は同じボーンの中だけで行い、関節が開いても穴が見えないようにした。
- **設定（D 専用）**：粒度（0.1〜0.4）、キャラクターの粒度（0.04〜0.12）、花を立方体で立てる、草の立体化（表示密度 0〜100 %）、立方体の縁の暗さ、隅の陰（AO）、裏向きの面の組を描かない。
- **資源**：D を使わない間は GPU 資源を持たない。CPU 側のボクセルは直前の 1 組を保持し、方式を戻したときは GPU へ上げ直すだけにした。

## 比較表（実測）

### 性能（性能ベンチマーク：カメラ回転中 240 フレーム、GPU 時間は EXT_disjoint_timer_query）

| 方式 | 標準視点 GPU | 遠景（ズーム 33）GPU | CPU（更新 + 描画命令） | 描画数 | 単位 |
| --- | --- | --- | --- | --- | --- |
| A：ポイント | 2.76 ms | 3.21 ms | 0.28 ms | 424,897 | 粒 |
| B：Gaussian Splats | 2.45 ms | 2.86 ms | 0.57 ms | 424,897 | スプラット |
| C：サーフェル | 2.44 ms | 2.32 ms | 0.30 ms | 424,897 | 円盤 |

- FPS・フレーム時間は 4 方式とも 75.0 FPS / 13.33 ms（画面の更新間隔で頭打ち）。差は GPU 時間にしか出ない。

## 直接比べられない指標と理由

| 指標 | 理由 |
| --- | --- |
| 描画数 | A・B・C は「点 1 つ」、D は「面（四角形）1 枚」。1 ボクセル = 0〜6 面なので数をそのまま比べられない。D はボクセル数（占有・表面）も別に表示する |
| B の断片数 | Spark 内部のシェーダーなので計測用シェーダーに差し替えられない。CPU 推定値（同じ式を A に当てた誤差 +0.005 %） |
| B の「奥が見える」 | B は深度を書かない |
| FPS | 画面の更新間隔で頭打ち。負荷の差は GPU 時間で比べる |
| 生成時間 | A・B・C は起動時の粒生成を共有、D は方式を選んだときに CPU でボクセル化する（開発ビルドの値は本番ビルドより遅い） |
| 形状の出どころ | D の樹木・岩・キャラクターの立体は、形状データの設定にかかわらず常に SDF の内外判定。「既存の粒 / SDF」の設定は D では色の写し元だけを変える |

## 長所・短所（技術的な事実）

| 方式 | 長所 | 短所 |
| --- | --- | --- |
| A | 生成が最も単純、既存表現そのもの | 断片/画素が多い（18.7）。移動時の変化が最大（9.8 %、縁のディザ模様を含む） |
| B | 面のつながりが最もなめらか | 初回に Spark（973 kB gzip）の読み込みが要る。CPU 時間が 2 倍（並べ替え）。深度がなく奥行きの輪郭が出ない。歩行・走行で腕が体から離れて見える |
| C | 断片/画素が A の半分、移動時の変化が最小 | 浅い角度で円盤が細くなり隙間が増える（空 0.13 %） |
| D | GPU 時間が最小（1.6 ms）、断片/画素 ≒ 2（重ね塗りがほぼない）、原理的に隙間がない、アニメーションの変化が最小 | 方式を選ぶたびに CPU でボクセル化（既定 0.55〜0.9 s、0.1 では約 3.7 s で画面が止まる）。小さな草・つるは粒ほど再現できない（草は既定で立てない、つるは地面の色だけ）。粒度より細かい形は段差になる |

## 見た目の評価（主観。好みの問題で、技術的な優劣ではない）

- D は「立方体の積み木」としてはっきり区別できる見た目で、地形の等高線状の段々、樹冠の層、雲のブロックが出る。A〜C の「ドット絵の粒」とは別の画風。
- 草を立方体にすると（`d-variants.png` の右端、草 50 %）地面がでこぼこして側面の影で暗い点が増え、にぎやかすぎると感じたので、既定は「花だけ立てる」にした。
- キャラクターは一辺 0.06 で 23 段ほど。目・頬は 1〜2 ボクセルの色のかたまりになり、粒の表現より記号的になる。
