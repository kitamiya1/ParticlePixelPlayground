## 方式 E の実装の要点

- **ポリゴンメッシュ**：通常の三角形メッシュ（`THREE.BufferGeometry` + インデックス）を 1 フレームに 7 ドローコール程度で描く。
  - 地形：`Terrain.heightRaw / bottomAt / edgeRadius` から極座標の同心円の網（間隔 0.25）で上面・底面・縁の側面を張る（縁の形は粒・ボクセルと同じ関数）。
  - 樹木・岩：方式 D と同じ SDF（`canopySdf / barkSdf / rockSdf`）を **Surface Nets** で三角形化。法線は格子値の差（追加の SDF 評価なし）。
  - キャラクター：部位 SDF（`characterSdfParts`）を部位 = ボーンごとに三角形化し、ボーン行列で剛体として動かす（A・D と同じ `CharacterRig`）。
  - 草・花・雲：粒の生成時に形の計画（葉の根元・長さ・傾き・色、花の位置・茎・色、雲のかたまりの中心・半径）を `visual/meshHints` に書き留め、葉は細い帯（三角形 5 枚）、花は茎 + 星形の円盤（10 枚）、雲は楕円体にする。記録は乱数を消費しないので A〜D の結果は変わらない（画素単位で確認済み）。
  - 色・焼き込み日照・風の影響度：A〜D と共通の点群から近くの点の値を写す（色は最も近い点、日照・風は半径 0.22 の加重平均）。
- **ドット絵化**：A・C・D と同じ `PixelPipeline`（低解像度描画 → 深度差の輪郭 → Bayer ディザ → パレット減色 → 整数倍拡大・サブピクセル補正）。画素サイズ・パレット・ディザ・輪郭は共通設定で効く。
- **光と陰影**：A〜D と同じ `LIGHTING_CHUNK`。風は頂点シェーダーで動かし、光は**画素ごと**に計算する（陰影の段階化が三角形の補間でぼけない）。E 専用に「フラットシェーディング」（画面微分から三角形の面の向き）を用意。
- **アニメーション**：キャラクターはボーンごとの剛体、樹木・草花は風で揺れる（メッシュの頂点は揺れの位相を共通にして形が崩れないようにした）。
- **設定（E 専用）**：形状の細かさ（0.2 / 0.14 / 0.1 / 0.07。作り直す）、フラットシェーディング、草の葉の表示密度（作り直さない）。プリセット「ピクセル化メッシュ：標準 / ローポリ / トゥーン」。
- **資源**：E を使わない間は GPU 資源を持たない。CPU 側のメッシュは直前の 1 組と点群の索引を保持し、方式を戻したときは GPU へ上げ直すだけ（96 ms）。

### 元の形状との違い（記録）

| 対象 | A・B・C（既定の「変換」） | D | E |
| --- | --- | --- | --- |
| 地形 | 地表・崖の粒 | 高さ場の柱 | 同じ高さ場の関数から作った網（間隔 0.25。粒の間隔 0.15 より粗いので、地面の色むらはやや大きくなめらか） |
| 樹木・岩 | 球・円錐の表面に並べた粒 | SDF の内外判定 | 同じ SDF を三角形化。輪郭はなめらかな和集合とノイズのでこぼこになり、粒版の「球の寄せ集め」とは縁の形が少し違う |
| キャラクター | 部位の表面の粒 | 部位 SDF のなめらかな和集合 | 部位 SDF を部位ごとに別メッシュ（剛体）にしたため、首・肩・股のなめらかなつなぎ（smin）が無い（関節は重なりで隠す） |
| 草 | 葉 1 枚 = 粒 2〜6 個（直径約 2 画素） | 既定は立てない | 同じ葉の計画から細い帯（幅 0.07 ≒ 1 画素）。粒より細く、草むらのふわっとした塊感は弱い |

| 雲 | 楕円体の表面の粒（下側を省く） | 粒の半径の球を埋める | 同じかたまりの楕円体（下側 dy = −0.45 で平らな底） |
| 色 | 粒の色 | 近くの点の色 | 近くの点の色を頂点に写し、三角形の中は補間 |

## 直接比べられない指標と理由

| 指標 | 理由 |
| --- | --- |
| 描いた数 | A・B・C は点 1 つ、D は面（四角形）1 枚、E は三角形 1 枚。1 ボクセル = 0〜6 面、1 粒の面積も三角形とは違うので数をそのまま比べない |
| B の断片数・奥行き | Spark 内部のシェーダーなので計測用に差し替えられない（CPU 推定）。深度を書かないので「奥が見える」は無し |
| B の GPU メモリ | Spark 内部の資源（バッファではなくテクスチャ）なのでバイト数を数えていない |
| FPS | 画面の更新間隔で頭打ち。負荷は GPU 時間で比べる |
| 生成時間 | A・B・C は起動時の粒生成（780 ms）を共有、D・E は方式を選んだときに CPU で作る |
| 形状 | D・E の樹木・岩・キャラクターは常に SDF。「既存の粒 / SDF」の設定は D・E では色の写し元だけを変える |
| アニメーションの変化率 | 前回（`abcd-report.md`）と切り出し範囲・ズームが違う |

## 見た目の評価（主観。好みの問題で、技術的な優劣ではない）

- E は「3D ゲームを低解像度で描いたドット絵」（いわゆる 3D ピクセルアート）の見た目。樹冠・岩は面の陰影がはっきりし、A〜C の「粒の集まり」より塊として読みやすい一方、粒の細かいざらつき（手描き風の質感）は減る。
- フラットシェーディング + 細かさ 0.2（プリセット「ローポリ」）は面の切り替わりがはっきり出て、ローポリ調のドット絵になる。
- 草は細い帯なので、A の「もこもこした草むら」より地面がすっきり見える。にぎやかさを求めるなら A〜C、読みやすさなら D・E という印象。
- キャラクターは E が最も輪郭がはっきりし、顔（目・頬）も見える。A〜C は同じ向きでも髪色の粒が顔を覆って見えにくい（既存の表現差。今回の変更によるものではない）。

| アニメーション | ボーンの粒 | スキニング（継ぎ目に課題） | ボーンの円盤 | ボーンの剛体 | 剛体 / 通常のスキニングに拡張可能 |
| 当たり判定・影・LOD との相性 | 別途 | 別途 | 別途 | 格子と一致 | メッシュをそのまま使える |

まとめ：**量産するゲームの本命は E**（既存の 3D 制作手順に乗り、負荷が予測しやすく、アニメーションが安定）、**画風重視の積み木表現なら D**、**粒の質感そのものが魅力なら A / C**（C の方が軽い）。B は見た目のなめらかさはあるが、読み込み・CPU 負荷・深度なしの点でゲーム向きではない。

## 技術的な制約・未検証事項・既知の不具合

- **実機スマホは未検証**。スマホの結果はデスクトップ GPU 上のエミュレーション（画面サイズ・タッチ・DPR）で、性能値はスマホの値ではない。
- 他ブラウザ（Safari・Firefox）、他 GPU、透視投影での全項目の比較は未実施（透視投影は E で表示できることのみ確認）。
- E の初回の三角形化はメインスレッドで行うため、既定で約 1.1〜1.5 s 画面が止まる（細かさ 0.07 で約 4 s）。Web Worker 化・事前生成が今後の課題。
- E はカリング（視錐台・距離による LOD）をしていないので、近距離でも島全体の三角形を描く。
- E のキャラクターは部位ごとの剛体なので、関節は重なりで隠しているだけ（大きく曲げると継ぎ目が見える可能性）。
- E の草は 1 画素前後の帯なので、稜線で空が透ける（0.15 %、浅い角度）。つたは再現していない。
- GPU 時間は 1 回の計測で ±0.3 ms ぶれる。順位の判断は複数回の結果による。
- JS ヒープの値は GC のタイミングに左右される目安。

## 再現方法

1. `npm run dev` で起動し、Playwright で 1280×800 のページを開く。
2. `window.__ppp` でゲーム更新を止め（`game.update` を空にし、`rig.update` の dt を 0 に固定）、`window.__shots` に撮影一覧を入れて `tools/capture.js` を実行。
3. `python docs/compare/tools/make_sheets.py` でコンタクトシートを作る。
4. 性能・ちらつき・隙間はパネルの「方式の比較・計測（A〜E）」のボタン（結果は `window.__ppp.lastReport`）。
