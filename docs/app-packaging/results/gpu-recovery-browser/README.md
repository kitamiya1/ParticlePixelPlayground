# 描画の喪失と復旧（AquaGpuGuard）：ブラウザでの試験（2026-11-27）

- 場所：開発機（Windows 11・RTX 2060 SUPER）の Claude デスクトップアプリの内蔵ブラウザ（Chromium 156）、`npm run dev`（Vite）の `aquarium.html`
- 方法：ページの中で `WEBGL_lose_context` の `loseContext()` / `restoreContext()` を呼ぶ（= 模擬。GPU 処理が本当に止められたわけではない）。
  iOS で実際に GPU 処理が止められる場合は CI で別に試す（`../ios-simulator-ci-2/`）
- 掘る・状態の読み取りは `window.__aqua`（`dig`・`digAim`・`step`・`world.dig`・`crab.sandHeld`・`gpu`・`diagLog`）

## 1. その場で復旧（失う → 1.5 秒後に復旧）・`?nosave`

| | 穴 | 手持ちの砂 | 掘った形（prims） | 位置 |
| --- | --- | --- | --- | --- |
| 失う前 | 6 | 3.062 | 48 | (−4.003, 5.002) |
| 復旧後 | 6 | 3.062 | 48 | (−4.003, 5.002) |

- 失っている間：`gpu.state = lost`、知らせ「描画が中断されました。立て直しています…（進捗は保存しています）」
- 復旧：`webglcontextrestored` → シェーダー 26 個を 1 つずつ作り直す（602 ms）→ `ready`、知らせを消す。作り直し後のシェーダーの数は 26 のまま（余分に作らない）
- 復旧後の画面：掘った穴・テクスチャが元どおり（目視）

## 2. 復旧の知らせが来ない → 保存して読み込み直す（IndexedDB に保存）

| | 穴 | 手持ちの砂 | prims | 位置 | 保存先 |
| --- | --- | --- | --- | --- | --- |
| 失う前 | 4 | 2.48 | 32 | (−2.00, 5.00) | indexeddb |
| 読み込み直した後 | 4 | 2.48 | 32 | (−2.01, 5.00) | indexeddb（status ok） |

- 失った直後に保存（`save flush (lost) ok`）→ 8 秒待って復旧が無い → もう一度保存して `location.replace`
- 読み込み直した後：「描画を立て直すため読み込み直しました（進捗は保存してあります）」の知らせ、記録 `gpu: this page was reloaded 6.2s ago to recover rendering`

## 3. 繰り返しの防止

- 読み込み直してから 5 分以内にまた失い、復旧が来ない → **読み込み直さない**（`failed`）。「保存して読み込み直す」ボタンを出す
- その後に遅れて復旧が来た → その場で立て直す（`ready`）
- 2 分の間に 4 回失った → `failed`「描画が何度も中断されました（2 分に 4 回）。自動での立て直しを止めました。」。自動の読み込み直しは 0 回
- ボタン「保存して読み込み直す」を押す → 保存して読み込み直し、穴 4・砂 2.48・prims 32 のまま

## 4. 起動時のシェーダーの準備（`view.prepare`）

- シェーダー 26 個を最初のフレームより前に 1 つずつ作る：初回 2070 ms（Vite の開発サーバー、シェーダーのキャッシュ無し）、2 回目以降 600〜690 ms
- 最初のフレーム 103 ms・2 枚目 14 ms・3 枚目 6 ms。最初の 3 枚でシェーダーの数は増えない（準備で全部作れている）
